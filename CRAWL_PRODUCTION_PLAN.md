# Production crawling and display-evidence system

## Context
Build production incrementally after the [probe plan](CRAWL_PROBE_PLAN.md#L18). Replay selects a discovery policy, not a live strategy or cadence. Then verify one explicitly authorized direct-only source through bounded one-shot epochs; expand only after the evidence lifecycle works end to end. PostgreSQL, S3-compatible storage and an authenticated read API support that slice. Hatchet Cloud, recurring refresh, distributed workers and paid operations have separate gates below. Protect proven refresh commitments from discovery spend.

## Findings and dependency status
The repository contains research directories and no implemented engine. Treat step-1 interfaces as planned until delivered and verified. Require the probe's held-out decision report and behavioral checks before selecting a production discovery policy; an inconclusive replay does not authorize a live policy by default. Reuse the effective probe policy, URL/origin and robots safety, classifiers and accounting semantics rather than creating a second crawler. The first production acceptance slice uses one direct-only fixture source, two successful one-shot epochs with a changed claim, an intervening failure and recovery, and observations visible through the authenticated API. Prove it with a locally driven PostgreSQL work queue before enabling Hatchet dispatch.

Verified service contracts:
- https://docs.hatchet.run/v1/tasks documents `@hatchet.task(name=..., input_validator=...)` with `(input, ctx)` arguments.
- https://docs.hatchet.run/v1/workers documents `hatchet.worker(name, slots=..., workflows=[...]).start()` and `HATCHET_CLIENT_TOKEN`. Slots are per-worker, not global.
- https://docs.hatchet.run/v1/cron-runs documents `hatchet.workflow(name=..., on_crons=[...])`; cron enqueues work, not a guarantee of start time, and Cloud meters task runs.
- https://docs.hatchet.run/v1/idempotency documents status/TTL deduplication and `task.aio_run(input=..., wait_for_result=False)`. Deduplication expires; PostgreSQL uniqueness must protect durable effects.
- https://www.postgresql.org/docs/current/sql-select.html documents row locking and `FOR UPDATE SKIP LOCKED`.
- https://docs.aws.amazon.com/AmazonS3/latest/userguide/conditional-writes.html documents conditional PUT with `If-None-Match: *`, including 412 on existing keys. Require equivalent behavior from the selected S3-compatible service.

Retain Python >=3.12, `src/now_on_display`, deterministic source IDs from canonical entry URLs, separate institution identities, immutable snapshots and the probe's evidence and direct-admission contracts. Offline `nod-probe replay` remains self-contained and never uses production state or services. Production uses PostgreSQL/S3 as its live authority and imports completed probe archives as historical evidence. The probe's separately gated Zyte/OpenAI milestones are not production prerequisites.

## Approach

### 1. Cut persistence over without losing probe evidence or spending state
Add psycopg 3 with connection pooling, SQLAlchemy Core/Alembic for migrations, boto3, FastAPI and uvicorn to pyproject.toml; defer hatchet-sdk and paid SDKs to their respective milestones. Resolve compatible versions into the lock file. Use PostgreSQL 17 or newer. Paths here are proposed additions/changes.

Add `db.py`, `migrations/`, `import_probe.py` and `nod-engine = now_on_display.production_cli:main`. Use SQLAlchemy Core for schema/query construction, not an ORM. Migrate live campaign persistence and snapshots to PostgreSQL/S3 and remove the old writable live SQLite path after acceptance. Retain local SQLite and local snapshots only for offline replay; never share live budgets or dispatch across backends. Reuse parser, evidence and admission rules. Module paths without a directory prefix are under `src/now_on_display/`; Alembic files live in root `migrations/`. Live commands use DATABASE_URL/S3, not `--state`; direct operators to archive import for old live state.

Provide `nod-engine migrate` and `nod-engine import-probe --state PATH --campaign NAME`. Require the archive writer lock and a terminal campaign; refuse running/in-flight campaigns, missing snapshots, unsupported schema versions and conflicting IDs. Preserve deterministic IDs, archive provenance (including replay versus live), historical costs, uncertain reservations, evidence and versions. Stage the import, validate counts/references, verify snapshots under the same storage protocol as live writes, then publish SQL references in one transaction. Retry idempotently by archive fingerprint. Failed publication leaves no visible campaign; uploaded or uncertain blobs remain charged to storage until reconciled. Never delete the old archive. Imported monetary liabilities reduce availability until reconciled, including across budget windows; replay attempts do not create provider liabilities or fresh coverage.

Extend persisted entities with UUID primary keys except existing deterministic institution/source IDs and snapshot hashes:
- `source_strategies(source_id, version, config_json, config_hash, evidence_run_id, state, activated_at)`; unique source/version; states candidate, active, retired. Runs pin an immutable version.
- `source_policies(source_id, state, freshness_seconds, budget_config, next_due_at, last_complete_check_at, schedule_hold_epoch_id)`; state candidate, pilot, active, paused. Require source-specific freshness_seconds for recurring active state only; no default. A non-null schedule hold excludes the source from cron without changing its coverage, last complete check, or overdue deadline.
- `refresh_epochs(id, source_id, strategy_version, due_at, started_at, completed_at, status, coverage_json)` and `work_units(id, epoch_id, purpose, url, extraction_version, state, attempt_count, next_attempt_at, lease_token, lease_until)`; unique epoch/purpose/canonical URL.
- `outbox(id, work_batch_id, state, next_attempt_at, dispatch_generation, claim_by_at, hatchet_run_id)`; `work_batches(id, kind, state, lease_token, lease_until)` plus batch-membership rows.
- `host_policies(hostname, min_delay_seconds, next_start_at, active_attempt_id, blocked_until)` for hostname-wide spacing/cooldown; `origin_robots(origin, robots_snapshot, robots_checked_at, policy_state)` keyed by scheme, hostname and effective port.
- `budget_windows`, `budget_accounts`, `reservations`, `settlements` and `operator_audit` as specified below.

Extend step-1 attempts/snapshots/responses/classifications rather than duplicating their ledgers. All times are timezone-aware UTC, money integer micro-USD, all foreign keys enforced. Add indexes for due active sources, queued work by next_attempt_at, unsettled reservations, host active attempts, source-object identity and observation history.

Use private content-addressed S3 keys `snapshots/sha256/{first_two_hex}/{hash}`. Use conditional single-part PUT with a service-validated full-object SHA-256. After a 412 or uncertain upload, verify the existing body's length and a service-validated full-object SHA-256, or stream and hash the body; user metadata and ETag are not proof. Fail closed on mismatches. Publish SQL references, observations or successful coverage only after verification. Raw HTML is never served by the API.

Use one durable storage ledger for imports and workers. Reserve worst-case decoded bytes before fetch; before PUT transfer actual bytes atomically to a unique per-hash storage claim and release the excess. Every PUT is attached to that claim before dispatch. Settle to one charged object only after verified presence; keep unresolved PUTs and physically present unreferenced blobs charged until reconciled, even if SQL publication fails. A missing HEAD is not proof that a timed-out PUT cannot still commit. Reuse or attach only after verification. Use a dedicated snapshot namespace with no unmanaged writers and no hidden retained versions. Report storage/API/Hatchet/cloud charges separately from provider spending.

Provide a bounded storage reconciliation command, read-only by default. Reclaim an unreferenced blob only during an explicit maintenance run with fetch/import writers stopped, outstanding PUTs resolved, and no published or staged reference; verify deletion before releasing capacity. An uncertain late PUT blocks reclamation, not quota accounting. Retain referenced history; if it fills the quota, defer writes and require an audited quota increase or separately approved retention policy rather than deleting evidence.

### 2. Activate explicit source and extraction contracts
Add `strategy_config.py` and extend `production_cli.py` with:
- `strategy validate --file PATH`: offline schema validation.
- `strategy preview --source ID --file PATH --snapshot HASH ...`: run extraction on stored samples, print evidence and validation failures without changing active state or making network calls.
- `source pilot --source ID --strategy PATH --policy PATH --authorization REF`: bind a pre-existing, operator-issued one-shot grant for the exact source and strategy. Require an eligible probe decision and a successful preview on at least one provenance-verified sample of each selected surface. No cron or inferred cadence. Reject unknown grant references; a CLI argument or audit note cannot mint authority.
- `source activate --source ID --strategy PATH --policy PATH`: enable recurring work only with recorded successful live pilot evidence and an authorized repeat-observation study supporting an explicit freshness interval, revisit unit and feasible request/time budget for every selected surface. The evidence must match the proposed strategy hash, origins, surfaces and execution mode; changes to those invalidate the gate. Pin the evidence references to the activated version; replay and previews cannot substitute for live evidence.
- `source pause --source ID --reason TEXT`: stop new admissions and dispatch; already-sent requests settle normally.
- `source status --source ID`, `budget status`, `epoch resume --id ID`, `epoch supersede --id ID --reason TEXT` and `refresh enqueue --source ID [--authorization REF]`: auditable operations. Pilot enqueue requires a grant; active enqueue follows the recurring policy. Only the later paid milestone adds `attempt reconcile --id ID --actual-usd DECIMAL --evidence TEXT`.

Persist each one-shot authorization as a revocable grant with a stable ID, immutable strategy hash, source, permitted origins/surfaces, expiry, and aggregate request, byte and elapsed-time caps. `refresh enqueue` atomically consumes the grant and pins it to one epoch; retrying the command must return the same epoch, including after terminal failure. Recheck expiry, revocation and remaining limits on each request, including robots and redirects; close incomplete if authorization expires or is revoked. A revisit study requires its own explicit grants for additional one-shot checks. Imported fixture and replay records never count as live-pilot or repeat-study proof.

Add `venue upsert --id UUID --institution ID --name TEXT --address-json PATH` to create/update explicit venues without changing their identity, and `venue list --institution ID`; reject missing institutions and conflicting institution changes. Strategy venue mappings must reference existing venue IDs. Optional address JSON must be an object; its absence does not authorize inferred geography.

Use strict versioned JSON strategy files (schema_version=1), with `source_id`, `probe_run_id`, explicit `allowed_origins`, and `surfaces[]`. Each surface specifies `id`, `kind` (feed, listing, object), `entry_urls`, `fetch_tier` (direct, zyte_http, zyte_browser), `enumeration` (json_next, html_next, sitemap, known_objects), and extraction config. Unknown origins never become automatically authorized in production; new origins/template families go to the probe queue. Preserve per-host robots and DNS/redirect checks from step 1.

Extraction config specifies `record_selector` (CSS for HTML or RFC6901 pointer for JSON array), field selectors in the same syntax, and optional per-record relative object links. HTML selectors extract text by default or a named attribute through a separate `attribute` field; do not accept executable Python, XPath extensions, model-generated code or arbitrary HTTP methods. JSON pagination uses a configured next-URL pointer, HTML uses a configured next-link CSS selector; no synthesized numeric pagination unless the adapter explicitly implements it. Only observed GET links enter the frontier.

Fields: `source_object_id`, `title`, `artist`, `accession_number`, `wikidata_qid`, `display_status`, `venue_reference`, `room`, `valid_from`, `valid_to`, `exhibition_reference`. Require a stable identifier selector plus an explicit immutable `object_id_namespace` identifying its issuing catalog, or an explicit canonical-URL identity mode with its own namespace. Share a namespace across listing/detail surfaces only when they use the same identity authority. Supply `display_value_map` mapping exact normalized source values to on_display, not_on_display, unknown; unmapped values become unknown and flag drift. Resolve venue through reviewed institution/venue mappings, never hostname. Dates accept ISO8601 or one configured format and timezone; preserve precision and ambiguous dates as null with diagnostics. Date-only end uses the next local midnight as an exclusive UTC bound.

Each surface also declares required record fields, `refresh_scope` (all_enumerated, known_objects, listing_and_details), whether its work list explicitly asserts physical exhibition membership, and validator policy (default disabled). Known object coverage is labeled as such, not whole-institution coverage. An activated strategy may use deterministic selectors, the verified step-1 Omeka/IIIF adapters, or `llm_evidence` extraction on bounded unstructured pages. The latter requires its own per-window model-call cap and a successful preview; it never becomes the default parser for all templates.

Require policy fields `refresh_budget_usd`, `expansion_budget_usd`, `request_limit`, `model_call_limit`, `browser_call_limit`, `max_inventory_urls`, `max_snapshot_bytes` and `max_epoch_seconds`, with positive `freshness_seconds` only for recurring activation. Missing/invalid limits fail; zero paid budget is valid. Reject origins/tier features outside operator policy and recurring targets whose observed revisit cost/time cannot fit their interval. Admit unknown total volume only with coverage=unknown, not an SLA. Strategies are immutable versions; effective versions change at epoch boundaries, never on in-flight work.

### 3. Enforce distributed budgets and host politeness
Port step-1 `budget.py` to PostgreSQL; add `admission.py`. Global budget configuration contains a UTC daily window, daily provider-spend ceiling, refresh pool, expansion pool, monthly ceiling and global request/model/browser limits. Pool totals may not exceed daily ceiling. Source refresh allocations must fit the refresh pool; expansion cannot borrow refresh funds. Unused refresh funds remain protected until window close; no opportunistic borrowing. Discovery/backfill use only expansion; rechecking indexed display evidence uses refresh.

Reserve in one transaction locking accounts in fixed order: global month, global day, day/pool, day/pool/source, then operation counters. Check settled plus reserved plus requested maximum against every ceiling; increment all applicable reservations or none. Reserve snapshot bytes and request/call counters too. An admitted operation spanning midnight stays charged to its admission window; unresolved monetary/storage liabilities are additionally carried into current availability so opening a new window cannot erase exposure. Record carry as a liability reference, not duplicated accounting spend. New budget windows are immutable, idempotently created from explicit config; policy changes cannot lower ceilings below outstanding exposure.

Paid mode is separately authorized. Preserve probe opt-in, price ceilings, per-call token/byte/time bounds and no hidden retries. Paid HTTP sets `followRedirect: false` and separately admits each next hop. Disable any tier without verified provider-side destination enforcement before each connection, including browser redirects and subrequests; local DNS checks and post-fetch rejection cannot substitute.

Atomically claim a PostgreSQL-unique logical operation key with the reservation and in-flight row before dispatch. Key fetches by epoch, purpose, canonical target and tier; key model work by epoch, immutable response ID, bounded-input hash and classifier version including model, prompt, schema and adapter. Do not use batch ID, worker lease or Hatchet run ID in the key. Carry unresolved operations forward when resuming or superseding an epoch: a successor must not recreate unresolved predecessor work merely under a new epoch ID; block automatic replay of that work stream until an explicitly authorized, audited fresh check, never treat billing settlement as a recovered result. Unrelated work may continue. Above-ceiling charges freeze the provider globally until operator correction. Budget denial defers work, not evidence.

Before every target request acquire the exact host row and atomically check active_attempt_id, next_start_at and blocked_until, plus the requested origin's robots policy for content requests. Fetch robots under the same host, budget and destination checks, without requiring an already-fresh robots policy to fetch it. Do not reuse one origin's robots rules for another. One active request per hostname across workers, at least 2 seconds between starts or longer robots delay. Host contention leaves work queued. Refresh robots after 24 hours; distinguish path denial from unavailable policy. Persist 429 cooldown to parsed Retry-After (60-second fallback) across sources and workers; never shorten it. Never use paid tier to bypass auth, robots or rate limits. Disclose browser resource accounting limitations without relaxing destination checks.

Use attempt ownership tokens and DB time, heartbeats every 15 seconds, 120-second work lease and strictly bounded request deadlines (direct 20 seconds, paid 90 seconds). On losing the DB/lease, worker stops admitting requests and terminates its child process. Reclaim an expired host only after the last admitted request deadline plus 30 seconds and a successful lease takeover; uncertain paid billing stays reserved. State writes require the ownership token so stale workers cannot publish. This minimizes overlapping target requests but is not a claim to cancel provider-internal processing after client timeout.

### 4. Orchestrate bounded batches with Hatchet and a durable outbox
Use PostgreSQL as the durable queue, driven by a local single-worker runner for the first fixture slice. Later add `workflows.py`, `worker.py`, `scheduler.py`, `batch_runner.py` and the Hatchet `nod-planner` cron every five minutes. Under a transaction advisory lock, scan recurring active sources by due_at then source ID. Before creating work, lock the source policy row and recheck state, due time, open epoch and absence of a schedule hold in the same transaction that inserts epoch/batch/outbox rows. A PostgreSQL partial unique index enforces at most one open epoch per source (running or deferred).

Create the first recurring epoch on activation; one-shot pilot epochs require manual enqueue. After a complete epoch set the coverage timestamp to the earliest verified check across covered resources and schedule dispatch at that time plus freshness_seconds minus lead time (max of 5 minutes and last complete duration, capped at half the interval; absent duration use 1 hour with the same cap). Failed, partial and superseded epochs keep their original due date in history and never advance freshness.

Use standalone tasks `nod-fetch-batch` and `nod-extract-batch` with input `{batch_id: UUID, dispatch_generation: int}` and output `{batch_id, status, processed, deferred}`. Fetch batches contain at most 25 URL operations and run at most 120 seconds; extraction batches at most 25 snapshots and 120 seconds. Set Hatchet automatic retries to zero; recover from durable work status. Start workers with 4 slots per process; enforce at most 16 active batches globally in PostgreSQL by default. A Scrapy batch runs in a fresh child using the shared DB/S3, avoiding reactor restart and worker-loop blocking. JSON API adapters use the same fetch admission.

The planner commits a dispatch generation, claim deadline and retry count before calling `task.aio_run(..., wait_for_result=False)` outside the transaction. A returned run ID is a receipt, not a claim; record it only against the matching generation. The worker may claim only the current, unexpired generation on an eligible open batch. Re-arm an unclaimed generation after its DB-time deadline even if Hatchet acknowledged it. Recover remaining runnable work after a claimed worker's lease expires, subject to host and paid-attempt recovery and next_attempt_at. Old generations and duplicate claims are no-ops. Use bounded backoff and a persisted dispatch cap; exhausting it leaves the batch explicitly operator-blocked and the source overdue. Never rely on Hatchet TTL deduplication; include task-run counts in cost reports.

Publish the verified snapshot/response, extraction work and discovered URLs transactionally. Extraction publishes its completed check and observations and marks the unit done in one transaction. A complete epoch requires successful enumeration and extraction for its required scope. Temporary contention, transient outage or a renewable budget shortage leaves the epoch open and deferred until eligible, preserving checkpoints, counters and its pinned strategy. Resume only deferred work under those same limits. An exhausted nonrenewable epoch cap closes terminal partial; three direct failures on a required unit or a permanent extraction failure close terminal failed; neither resets counters, advances freshness nor auto-spawns a new epoch.

`epoch supersede` fences new admissions and publication for the old epoch; previously admitted attempts may settle in the ledger, and unsettled liabilities stay reserved. When an epoch becomes terminal partial, failed or superseded, atomically record the reason/checkpoint and set `schedule_hold_epoch_id` on the same source policy row the planner locks. This releases the open slot but does not make the source runnable by cron. Clear the hold only in the audited transaction that creates an eligible successor, or activates a different reviewed strategy and creates its first epoch; a pilot still requires an unused grant. Never reopen terminal epochs or clear the hold by restarting workers. Preserve overdue status until complete coverage. On shutdown stop admissions, terminate children after 30 seconds and retain uncertain reservations.

### 5. Enumerate depth, refresh coverage and detect drift
Extend delivered `crawl.py`, `discovery.py`, `adapters.py`, `classify.py` and `strategy.py`; reuse their bounded parsers, URL canonicalization, security and evidence validators. Production removes sampling caps only for explicitly activated surfaces, replacing them with the source's configured persistent inventory/request/byte/time limits. Keep probing as sampled work in the expansion pool.

For feeds/listings traverse observed next links with cycle detection and per-page checkpoints. Dedupe by source, object identifier namespace and normalized key. For sitemaps enumerate allowed documents/pages across batches; record exhaustion separately from truncation and never use lastmod to skip checks. For listing_and_details revisit listings plus indexed exhibition/detail URLs until successful extraction supplies explicit end dates/status. Unchanged listings do not exempt details. Freeze known_objects membership for an epoch; all_enumerated admits newly found records and completes only on exhaustion. Unknown families go to expansion probe candidates.

Any exhausted cap produces coverage=partial with remaining count or unknown lower bound. Full enumeration is only completeness of the configured surface, not a museum census; concurrent upstream mutations make non-snapshot APIs best-effort enumeration. Missing records, HTTP 404 and an object disappearing from a feed never imply not_on_display in this release. No incremental feed watermark is trusted to remove the periodic full configured-surface sweep.

Default to unconditional GET. Operators may enable validators for a surface only after at least three successful paired conditional/unconditional checks; every seventh successful refresh remains unconditional. A 304 stages verification for that resource using its last verified representation, not for the whole assertion scope. A missing/corrupt body forces a new unconditional request under a new reservation. A mismatch disables validators and marks affected coverage uncertain. Matching content hash and extraction version may reuse extraction; publish the resulting verification times only with the complete authoritative scope in §6. A partial check never refreshes an older published assertion.

Reprobe unknown templates and any surface where a required identity field disappears, a display value becomes unmapped, or 3 consecutive previously extractable pages yield zero records. Flag drift, retain old evidence as stale/overdue and pause affected surface expansion; do not erase history or call blank pages a successful refresh. Queue at most one reprobe per source/version per day under expansion budget. A new candidate strategy requires explicit activation; LLM output cannot rewrite production code/config.

### 6. Persist artwork identity and temporal display evidence
Add `extract.py`, `identity.py` and `observations.py`. Create:
- `venues(id, institution_id, name, address_json)` populated by operator mapping or explicit source identifiers; no guessed venue from hostname.
- `source_objects(id, source_id, object_id_namespace, source_object_key, canonical_url, metadata_json)` unique source/namespace/key. Do not merge identical raw keys from distinct catalogs or silently reinterpret an existing namespace.
- `artworks(id, created_at)` and `artwork_links(source_object_id, artwork_id, method, evidence_json, active)`; at most one active link per source object.
- `artwork_identifiers(artwork_id, namespace, authority_id, value, evidence_json)`; accession authority is owning institution, not current display venue.
- `exhibitions(id, source_id, source_exhibition_key, title, venue_id, valid_from, valid_to, evidence_json)` with source-key uniqueness.
- `assertion_checks(id, publisher_id, resource_scope_id, epoch_id, scope_generation, extractor_version, revision, coverage_at, completeness, supersedes_check_id)` record successful authoritative output, including a complete empty set. Attach each contributing response and verified snapshot in check-input rows, with per-resource checked_at. The reviewed strategy defines a stable publisher/resource scope independent of venue, with explicit mappings for authoritative replacement across URL or strategy changes.
- `display_observations(id, check_id, source_object_id, artwork_id_at_ingest, venue_id, room, display_status, valid_from, valid_to, source_url, snapshot_hash, evidence_json)`; display_status is on_display, not_on_display, unknown. Identify the supporting check inputs. Enforce unique check/source-object/assertion-hash; an epoch/scope/extractor revision publishes at most once.

Deterministic extraction follows the reviewed selector/adapter and display dictionary. Paid LLM extraction proposes the same fields with exact quotations and source block references, but only independently confirmed subject relationships may publish: a deterministic binding rule or an audited human review must verify the subject, assertion and venue; lexical match alone does not suffice. Unresolved fields stay null/unknown. Physical exhibition membership requires subject-bound physical participation, venue and applicable dates; online/catalogue mentions and a room string alone are not proof of display.

Create a new artwork for an otherwise unresolved source object. Automatically link only exact institution-scoped accession identity or an explicit artwork Wikidata QID extracted from its identifier field, never any QID mentioned in text. If identifiers disagree with existing mappings, create an identity-conflict record and do not merge. No fuzzy title/artist automatic merging. Provide audited `identity link --object ID --artwork ID --evidence TEXT` and `identity unlink --object ID --evidence TEXT`; unlink creates a separate artwork if needed. History retains artwork_id_at_ingest; queries resolve through current active links. Do not destructively merge/delete artwork rows.

Build the current view from complete authoritative checks per publisher/resource scope. Allocate a monotonic scope generation under the scope's owner lock at epoch start; stage only inputs required by the pinned strategy and enumerated in that same epoch. Publish the completed generation and replace the assertion set atomically while validating epoch ownership and the scope head. An older generation cannot replace a newer one. Archive imports are historical and never advance a live scope head. A correction links to its exact predecessor and may update the current view only if that generation is still current.

Keep ordering separate from freshness: set `coverage_at` to the oldest contributing check time, and retain each assertion's own evidence and check times. A 304 satisfies only its specific resource, with a verified body for the same representation and extraction under the pinned extractor; never carry forward the rest of an earlier generation. Failed, incomplete, drifted or unauthorized checks neither retire assertions nor advance their verification times. Complete replacement can remove assertions or report unknown without fabricating not_on_display. Independent publishers' scopes survive one another's replacements. Corrections and relinks update affected projections transactionally.

Expose per-assertion freshness (fresh, stale, unconfigured for a pilot without an interval), validity (current, future, ended, unspecified), and source evidence. Consolidate fresh applicable explicit assertions; an undated “on view” is a check-time statement that can qualify as currently reported while fresh, not a supplied validity interval. Distinguish disagreement from no qualifying assertions and flag simultaneous distinct venues for the same resolved physical artwork. Pilot evidence remains visible without qualifying as fresh recurring coverage. Stale/ended evidence remains historical; expiry never manufactures not_on_display. “Currently reported” is not independent confirmation.

### 7. Serve authenticated read access and operate managed containers
Add `api.py` using FastAPI, `metrics.py`, `Dockerfile` and `deploy/compose.yaml`. The compose file runs only API and worker containers against externally supplied managed PostgreSQL, Hatchet Cloud and S3; no paid provisioning, public website, Redis or embedded database. Run containers non-root with read-only root filesystem and bounded tmpfs for Scrapy children; external TLS termination is required. Secrets come from runtime environment/secrets, never committed files or request logs.

Configure DATABASE_URL (TLS outside tests), S3_BUCKET, S3_REGION, optional S3_ENDPOINT_URL, standard AWS credential chain, NOD_API_TOKEN_SHA256 for the API, and NOD_CONFIG_PATH. Require HATCHET_CLIENT_TOKEN only in orchestrated mode and paid credentials only for enabled paid tiers. `nod-engine check-config` verifies dependencies for the selected mode without exposing secrets. `nod-engine worker` uses the local queue in direct pilot mode and registers planner/fetch/extract workflows only in orchestrated mode; `nod-engine serve --host 0.0.0.0 --port 8000` starts the API. Run migrations explicitly, never at worker boot.

All /v1 and /metrics endpoints require Bearer token comparison against NOD_API_TOKEN_SHA256 using constant-time comparison; no query-string authentication. /health/live returns only process liveness; /health/ready returns 503 until SQL schema and storage connectivity are available, without credentials/details. Support token rotation by restarting with a new hash. API read-only DB role has no budget/admission mutations.

Implement `GET /v1/sources`, `/v1/sources/{id}`, `/v1/artworks`, `/v1/artworks/{id}`, `/v1/artworks/{id}/observations`, `/v1/display`, `/v1/runs/{id}` and `/v1/budgets`. List responses are `{items, next_cursor}` with limit default 50/max 200 and opaque base64url versioned keyset cursor; reject invalid cursors with 400. Artworks supports exact accession/QID and case-insensitive title/artist substring filters; display supports institution_id, venue_id, artwork_id, status and freshness. Detail endpoints return 404 for missing IDs. Dates are ISO8601 UTC; response schema_version=1. Return source URLs, checked times, evidence excerpts, validity/freshness, conflicts and coverage, never raw HTML, credentials or presigned snapshot links.

Add `nod-engine export --kind sources|artworks|observations|display --format jsonl` streaming the same query models without a whole-dataset allocation. Operator reports include oldest overdue source, complete/partial/unknown coverage counts, paused sources, actual/conservative/uncertain spending, request/browser/model/task counts and storage bytes. Prometheus metrics cover overdue age, run outcomes, queue age, reservations and provider errors; avoid raw URL/object ID labels. Emit structured audit/log events on activation, pause, budget denial, price-ceiling breach, drift and reconciliation.

Deployment sequence: verify replay and first offline direct-only slice; check configuration; migrate; import terminal archives; preview and run an explicitly authorized one-shot direct pilot; inspect readiness and API evidence. Prove repeated observations and source-specific capacity before activating recurrence; prove Hatchet recovery before distributed deployment. Enable managed PostgreSQL backups/PITR and bucket restrictions. `nod-engine verify-storage` checks referenced bytes in bounded pages; missing/corrupt evidence is unavailable and affected coverage partial.

Add `tests/production/compose.yaml` for isolated PostgreSQL 17 and an S3-compatible test service; fix ports at 55432/59000 and fail clearly if occupied. Tests use a test-only target transport and fixture server, never production seeds or paid APIs. Start with `docker compose -f tests/production/compose.yaml up -d --wait`, then `python -m pytest tests/production -q`. Test fixtures supply database/object-store endpoints and isolated buckets/schemas; no production credentials are read by this suite.

Required end-to-end checks, not source-text assertions:
1. Import a step-1 fixture archive twice: identical IDs/evidence/costs, one import, uncertain liability still reduces availability. Missing blob/conflicting ID fails without published partial import; local archive remains unchanged.
2. ## Assumptions and contingencies
- Managed infrastructure is operator-supplied. This plan builds deployable containers and verifies integrations; it does not purchase/provision accounts.
- Freshness is a source-specific, evidence-backed operating target, not a promise. Upstream publishing delays, budget exhaustion, robots restrictions and unknown volume can leave coverage overdue or unverified.
- Provider/model IDs, prices, policies and allowed origins come from validated configuration; no configured paid tier means direct/deterministic-only execution with unknown evidence where appropriate.
- If the step-1 implementation uses different internal symbol names, move its actual store/provider/parser callers to the contracts here, retaining behavioral tests; do not add compatibility backends or duplicate fetching logic.
- S3 services lacking conditional PUT/checksum verification are unsupported: fail configuration with `unsupported_object_store`, never silently overwrite evidence.
- No deterministic or reviewed extraction plan for a source means it remains candidate; the engine does not invent a parser or activate all directory seeds automatically.
