# Production crawling and display-evidence system

## Context
Implement step 2 after the budgeted probe engine in [CRAWL_PROBE_PLAN.md](CRAWL_PROBE_PLAN.md). Retain that plan unchanged. Production adds managed PostgreSQL, Hatchet Cloud orchestration, S3-compatible snapshots, containerized workers, an authenticated read API and operator CLI. Admit sources explicitly with a daily freshness target; protect refresh funding before discovery/backfill and expose overdue coverage rather than promising freshness beyond budgets.

## Findings and dependency status
The repository currently contains research directories and no implemented engine. Step-1 module paths and contracts are planned, not verified implementation. Before implementation, read the delivered step-1 package and tests; execute this plan only after its acceptance checks pass. If step 1 is missing, implement [CRAWL_PROBE_PLAN.md](CRAWL_PROBE_PLAN.md) first; do not substitute scaffolds for it. Reuse its URL safety, robots parsing, provider clients, classifiers and budget accounting semantics; migrate persistence rather than create a second crawler.

Verified service contracts:
- https://docs.hatchet.run/v1/tasks documents `@hatchet.task(name=..., input_validator=...)` with `(input, ctx)` arguments.
- https://docs.hatchet.run/v1/workers documents `hatchet.worker(name, slots=..., workflows=[...]).start()` and `HATCHET_CLIENT_TOKEN`. Slots are per-worker, not global.
- https://docs.hatchet.run/v1/cron-runs documents `hatchet.workflow(name=..., on_crons=[...])`; cron enqueues work, not a guarantee of start time, and Cloud meters task runs.
- https://docs.hatchet.run/v1/idempotency documents status/TTL deduplication and `task.aio_run(input=..., wait_for_result=False)`. Deduplication expires; PostgreSQL uniqueness must protect durable effects.
- https://www.postgresql.org/docs/current/sql-select.html documents row locking and `FOR UPDATE SKIP LOCKED`.
- https://docs.aws.amazon.com/AmazonS3/latest/userguide/conditional-writes.html documents conditional PUT with `If-None-Match: *`, including 412 on existing keys. Require equivalent behavior from the selected S3-compatible service.

Step-1 contract retained in this plan: Python >=3.12; package `src/now_on_display`; `nod-probe` CLI; SQLite run/frontier/attempt/classification/strategy ledger; content-addressed snapshots; Scrapy direct fetching, Zyte HTTP/browser clients, OpenAI structured classification; source IDs derived from canonical entry URLs; institutions are not collapsed by host. Paid calls reserve integer micro-USD before sending; uncertain outcomes remain reserved; robots, direct request limits, SSRF protection and bounded parsing apply to every fetch. Step 2 replaces SQLite/local snapshot runtime with PostgreSQL/S3, retaining read-only import of completed probe archives.

## Approach

### 1. Cut persistence over without losing probe evidence or spending state
Add psycopg 3 with connection pooling, SQLAlchemy Core/Alembic for migrations, boto3, hatchet-sdk, FastAPI and uvicorn to pyproject.toml; resolve exact compatible versions into the existing lock file. Retain step-1 dependencies and Python version. Use PostgreSQL 17 or newer. All paths in this section are proposed additions/changes, not claims they already exist.

Replace `src/now_on_display/store.py` SQLite runtime with PostgreSQL transactions; add `db.py`, `migrations/` and `import_probe.py`. Use SQLAlchemy Core for schema/query construction, not an ORM identity layer. Migrate every caller found by references to the delivered store API, including CLI, budget, frontier, reports and tests. Remove the old writable SQLite path and OS writer lock after migration acceptance; do not maintain two live budget authorities. Keep `nod-probe` as the actual probe command operating against PostgreSQL, not an alias to obsolete code. Add `nod-engine = now_on_display.production_cli:main` for production operations.

Module paths without a directory prefix in this plan are under `src/now_on_display/`; Alembic files live in root `migrations/`. Update every `nod-probe` runtime command to obtain DATABASE_URL/S3 configuration instead of `--state`; reject `--state` with guidance to `nod-engine import-probe`. Its seed import, probe, sources, report and reconciliation behaviors remain available against PostgreSQL. The archive importer is the only production reader of the old SQLite schema.

Provide `nod-engine migrate` and `nod-engine import-probe --state PATH --campaign NAME`. Import requires the old directory's writer lock and only terminal campaigns; refuse running/in-flight campaigns, missing snapshots, unsupported schema versions and conflicting IDs. Preserve deterministic institution/source IDs, all historical attempt costs, uncertain reservations, source snapshots, evidence and versions. Import tables into staging under an import UUID, validate counts/references/hash integrity, upload snapshots, then publish SQL rows in one transaction; retry the same import idempotently by archive fingerprint. A failed upload leaves no visible imported campaign; harmless unreferenced blobs can remain. Never delete the old archive. Imported uncertain liabilities count against the first production budget window until reconciled, even if originating before that window.

Extend persisted entities with UUID primary keys except existing deterministic institution/source IDs and snapshot hashes:
- `source_strategies(source_id, version, config_json, config_hash, evidence_run_id, state, activated_at)`; unique source/version; states candidate, active, retired. Runs pin an immutable version.
- `source_policies(source_id, state, freshness_seconds, budget_config, next_due_at, last_complete_check_at)`; state candidate, active, paused; default freshness 86400.
- `refresh_epochs(id, source_id, strategy_version, due_at, started_at, completed_at, status, coverage_json)` and `work_units(id, epoch_id, purpose, url, extraction_version, state, attempt_count, next_attempt_at, lease_token, lease_until)`; unique epoch/purpose/canonical URL.
- `outbox(id, work_batch_id, state, next_attempt_at, hatchet_run_id)`; `work_batches(id, kind, state, lease_token, lease_until)` plus batch-membership rows.
- `host_policies(hostname, robots_snapshot, robots_checked_at, min_delay_seconds, next_start_at, active_attempt_id, blocked_until)`; policies are exact-host keyed.
- `budget_windows`, `budget_accounts`, `reservations`, `settlements` and `operator_audit` as specified below.

Extend step-1 attempts/snapshots/responses/classifications rather than duplicating their ledgers. All times are timezone-aware UTC, money integer micro-USD, all foreign keys enforced. Add indexes for due active sources, queued work by next_attempt_at, unsettled reservations, host active attempts, source-object identity and observation history.

Replace `snapshots.py` local storage with S3 keys `snapshots/sha256/{first_two_hex}/{hash}`. Conditional PUT prevents overwrites; on 412 confirm stored length/hash metadata, otherwise fail corruption checks. Mark SQL snapshot available only after upload verification. Upload failure cannot yield published observations or successful coverage. Raw HTML stays private, never served by API. Keep referenced snapshots indefinitely in this release; enforce an operator-specified storage-byte quota before fetching/uploading, and defer work when exhausted. Storage/API/Hatchet/cloud charges are reported separately from provider spend, not falsely claimed to be fully dollar-capped.

### 2. Activate explicit source and extraction contracts
Add `strategy_config.py` and extend `production_cli.py` with:
- `strategy validate --file PATH`: offline schema validation.
- `strategy preview --source ID --file PATH --snapshot HASH ...`: run extraction on stored samples, print evidence and validation failures without changing active state or making network calls.
- `source activate --source ID --strategy PATH --policy PATH`: atomically create/activate a strategy version and policy after checks below. Require a probe run ID and successful preview references on at least one sample of each selected surface; classification alone cannot authorize a crawl.
- `source pause --source ID --reason TEXT`: stop new admissions and dispatch; already-sent requests settle normally.
- `source status --source ID`, `budget status`, `attempt reconcile --id ID --actual-usd DECIMAL --evidence TEXT`, `epoch resume --id ID` and `refresh enqueue --source ID`: auditable operations; resume never resets limits or replays uncertain paid calls.

Add `venue upsert --id UUID --institution ID --name TEXT --address-json PATH` to create/update explicit venues without changing their identity, and `venue list --institution ID`; reject missing institutions and conflicting institution changes. Strategy venue mappings must reference existing venue IDs. Optional address JSON must be an object; its absence does not authorize inferred geography.

Use strict versioned JSON strategy files (schema_version=1), with `source_id`, `probe_run_id`, explicit `allowed_origins`, and `surfaces[]`. Each surface specifies `id`, `kind` (feed, listing, object), `entry_urls`, `fetch_tier` (direct, zyte_http, zyte_browser), `enumeration` (json_next, html_next, sitemap, known_objects), and extraction config. Unknown origins never become automatically authorized in production; new origins/template families go to the probe queue. Preserve per-host robots and DNS/redirect checks from step 1.

Extraction config specifies `record_selector` (CSS for HTML or RFC6901 pointer for JSON array), field selectors in the same syntax, and optional per-record relative object links. HTML selectors extract text by default or a named attribute through a separate `attribute` field; do not accept executable Python, XPath extensions, model-generated code or arbitrary HTTP methods. JSON pagination uses a configured next-URL pointer, HTML uses a configured next-link CSS selector; no synthesized numeric pagination unless the adapter explicitly implements it. Only observed GET links enter the frontier.

Fields: `source_object_id`, `title`, `artist`, `accession_number`, `wikidata_qid`, `display_status`, `venue_reference`, `room`, `valid_from`, `valid_to`, `exhibition_reference`. Require a stable object ID selector or explicit `canonical_url` identity mode. Supply `display_value_map` mapping exact normalized source values to on_display, not_on_display, unknown; unmapped values become unknown and flag drift. Venue references resolve through explicit strategy mappings to institution/venue IDs; a shared host never implies a venue. Dates accept ISO8601 or one configured strptime format/timezone; ambiguous dates stay null with diagnostics. Store source precision; a date-only end includes that local date through next midnight, converted to an exclusive UTC bound. A future or ended exhibition is not current.

Each surface also declares required record fields, `refresh_scope` (all_enumerated, known_objects, listing_and_details), whether its work list explicitly asserts physical exhibition membership, and validator policy (default disabled). Known object coverage is labeled as such, not whole-institution coverage. An activated strategy may use deterministic selectors, the verified step-1 Omeka/IIIF adapters, or `llm_evidence` extraction on bounded unstructured pages. The latter requires its own per-window model-call cap and a successful preview; it never becomes the default parser for all templates.

Activation requires policy fields `refresh_budget_usd`, `expansion_budget_usd`, `request_limit`, `model_call_limit`, `browser_call_limit`, `max_inventory_urls`, `max_snapshot_bytes`, `max_epoch_seconds` and optional freshness_seconds. Missing/negative limits fail; zero paid budget is valid for direct-only sources. Reject strategy origins/tier features outside operator configuration and targets whose minimum known request-time estimate already exceeds their freshness interval. Unknown total volume is admitted with coverage=unknown, never a guaranteed SLA. New strategies take effect only on new epochs; active epochs finish or are explicitly paused.

### 3. Enforce distributed budgets and host politeness
Port step-1 `budget.py` to PostgreSQL; add `admission.py`. Global budget configuration contains a UTC daily window, daily provider-spend ceiling, refresh pool, expansion pool, monthly ceiling and global request/model/browser limits. Pool totals may not exceed daily ceiling. Source refresh allocations must fit the refresh pool; expansion cannot borrow refresh funds. Unused refresh funds remain protected until window close; no opportunistic borrowing. Discovery/backfill use only expansion; rechecking indexed display evidence uses refresh.

Reserve in one transaction locking accounts in fixed order: global month, global day, day/pool, day/pool/source, then operation counters. Check settled plus reserved plus requested maximum against every ceiling; increment all applicable reservations or none. Reserve snapshot bytes and request/call counters too. An admitted operation spanning midnight stays charged to its admission window; unresolved monetary/storage liabilities are additionally carried into current availability so opening a new window cannot erase exposure. Record carry as a liability reference, not duplicated accounting spend. New budget windows are immutable, idempotently created from explicit config; policy changes cannot lower ceilings below outstanding exposure.

Keep provider ceilings, opt-in, per-call token/byte/time bounds and no-hidden-retry semantics from step 1. An uncertain paid request blocks automatic replay of that operation, not unrelated sources. Reconciliation is audited; above-ceiling actual charges freeze that provider globally until the operator corrects the configured ceiling. Ordinary workflow retries may resume unsent units but must never make an already-sent paid request again. Budget denial leaves work deferred with next eligible window, not failed/not-on-display.

Before every target request acquire the exact host row and atomically check robots, active_attempt_id, next_start_at and blocked_until; mark active before send. One active request per hostname across all workers and at least 2 seconds between starts, or larger robots delay. Host contention leaves work queued instead of occupying a sleeping Hatchet task. Refresh robots after 24 hours; outage/disallow behavior is the step-1 conservative policy. 429 blocks the host until parsed Retry-After, default 1 hour; 401/403 do not trigger paid bypass. Browser provider subrequests remain outside per-resource control and must be disclosed.

Use attempt ownership tokens and DB time, heartbeats every 15 seconds, 120-second work lease and strictly bounded request deadlines (direct 20 seconds, paid 90 seconds). On losing the DB/lease, worker stops admitting requests and terminates its child process. Reclaim an expired host only after the last admitted request deadline plus 30 seconds and a successful lease takeover; uncertain paid billing stays reserved. State writes require the ownership token so stale workers cannot publish. This minimizes overlapping target requests but is not a claim to cancel provider-internal processing after client timeout.

### 4. Orchestrate bounded batches with Hatchet and a durable outbox
Add `workflows.py`, `worker.py`, `scheduler.py`, `batch_runner.py`. Register a Hatchet workflow `nod-planner` with `on_crons=[\"*/5 * * * *\"]` and a single planning task. It takes a PostgreSQL transaction advisory lock; concurrent invocations exit without work. Scan overdue/approaching-deadline active sources, order by due_at then source ID, and persist epoch/work batch/outbox rows atomically. At most one nonterminal refresh epoch per source; a slow epoch stays overdue rather than spawning duplicates. Daily is a maximum desired age, not a guarantee cron starts on time.

Create first epoch immediately on activation. After success schedule the next dispatch at earliest covered-resource check time + freshness_seconds - lead time, where lead time is max(5 minutes, last complete epoch duration), capped at freshness_seconds/2. If no completed duration exists use 1 hour capped at half the interval. Completion records the minimum check time across covered resources as the coverage timestamp; do not pretend everything was checked at epoch finish. Failed/partial epochs retain their original deadline and do not advance freshness.

Use standalone tasks `nod-fetch-batch` and `nod-extract-batch` with input `{batch_id: UUID}` and output `{batch_id, status, processed, deferred}`. Fetch batches contain at most 25 URL operations and run at most 120 seconds; extraction batches at most 25 snapshots and 120 seconds. Set Hatchet automatic retries to zero; recovery comes from persistent work status. Start workers with 4 slots per process; default at most 16 active batches globally enforced in PostgreSQL. A Scrapy batch executes in a fresh child process using the shared DB/S3, avoiding reactor restart and worker-loop blocking; JSON API adapters use the same admission and fetch path, not a second HTTP bypass.

The planner dispatches pending outbox rows through `task.aio_run(..., wait_for_result=False)` and records returned run ID. Dispatch crash/timeout can create duplicate Hatchet runs: a transactionally claimed batch and per-unit ownership token allow only one to do work. No correctness depends on Hatchet TTL deduplication. Unacknowledged outbox rows are retried at the next planner tick, maximum once per tick; provider work remains deduplicated at attempt level. Do not enqueue one Hatchet task per URL or per wait. Include task-run counts in cost reports.

Fetcher saves snapshot/response, then extraction work and discovered URLs transactionally after successful object upload. Extraction publishes observations and marks the unit done in one SQL transaction. Planner finalizes an epoch only when all required enumeration and extraction units are terminal-success; errors/missing required fields retain partial status and block a complete-check claim. On 3 direct failures for one unit within an epoch (each paid tier still no automatic retry), mark failed, preserve the source's overdue status and require the next manually resumed attempt or next strategy intervention; prevent endless failure-spend loops. Graceful shutdown stops admissions, terminates child processes after 30 seconds and preserves uncertain reservations.

### 5. Enumerate depth, refresh coverage and detect drift
Extend delivered `crawl.py`, `discovery.py`, `adapters.py`, `classify.py` and `strategy.py`; reuse their bounded parsers, URL canonicalization, security and evidence validators. Production removes sampling caps only for explicitly activated surfaces, replacing them with the source's configured persistent inventory/request/byte/time limits. Keep probing as sampled work in the expansion pool.

For feeds/listings traverse every observed next link with cycle detection, persist checkpoints per page and dedupe records by source_object_id. For sitemaps enumerate all allowed documents/pages across batches, recording exhaustion versus cap/truncation separately; never use lastmod to skip display checks. For listing_and_details, each epoch revisits listings plus all currently indexed exhibition/detail URLs until a successful extraction provides explicit end dates/status; unchanged listings do not exempt details. For known_objects, freeze epoch membership at its start, refresh every member and record newly discovered members for the next epoch; all_enumerated adds newly found records to the running epoch and completes only on exhaustion. New unknown URL families become expansion probe candidates rather than silently excluded relevant content.

Any exhausted cap produces coverage=partial with remaining count or unknown lower bound. Full enumeration is only completeness of the configured surface, not a museum census; concurrent upstream mutations make non-snapshot APIs best-effort enumeration. Missing records, HTTP 404 and an object disappearing from a feed never imply not_on_display in this release. No incremental feed watermark is trusted to remove the periodic full configured-surface sweep.

Default unconditional GET each refresh. Store validators; operators may enable conditional requests for a surface only with recorded comparison evidence from at least 3 successful paired conditional/unconditional checks. Every seventh successful refresh remains unconditional. A 304 links to the last complete snapshot and updates verification time only for that resource; absent/corrupt previous body forces an unconditional request under a new reservation. Any mismatch disables validators and marks intervening coverage uncertain. Content hashes skip repeated extraction when extraction version and input match, but successful current checks still append a new verification observation. Freshness and source-asserted validity are separate.

Reprobe unknown templates and any surface where a required identity field disappears, a display value becomes unmapped, or 3 consecutive previously extractable pages yield zero records. Flag drift, retain old evidence as stale/overdue and pause affected surface expansion; do not erase history or call blank pages a successful refresh. Queue at most one reprobe per source/version per day under expansion budget. A new candidate strategy requires explicit activation; LLM output cannot rewrite production code/config.

### 6. Persist artwork identity and temporal display evidence
Add `extract.py`, `identity.py` and `observations.py`. Create:
- `venues(id, institution_id, name, address_json)` populated by operator mapping or explicit source identifiers; no guessed venue from hostname.
- `source_objects(id, source_id, source_object_key, canonical_url, metadata_json)` unique source/key.
- `artworks(id, created_at)` and `artwork_links(source_object_id, artwork_id, method, evidence_json, active)`; at most one active link per source object.
- `artwork_identifiers(artwork_id, namespace, authority_id, value, evidence_json)`; accession authority is owning institution, not current display venue.
- `exhibitions(id, source_id, source_exhibition_key, title, venue_id, valid_from, valid_to, evidence_json)` with source-key uniqueness.
- `display_observations(id, source_object_id, artwork_id_at_ingest, venue_id, room, display_status, observed_at, valid_from, valid_to, source_url, response_id, snapshot_hash, extractor_version, evidence_json, epoch_id, supersedes_id)`; display_status is on_display, not_on_display, unknown. Unique response/source-object/extractor-version/assertion-hash prevents duplicate publication on retries.

Deterministic extraction follows the active selector/adapter plan; explicit display values map through the reviewed dictionary. LLM extraction returns the same schema plus exact quotations and source block references, capped and validated like the probe classifier. Require identity and explicit status/location evidence; reject invented accession IDs, URLs, dates or venues. Unresolved fields stay null/unknown. An exhibition's artwork list supports a display observation only when the configured surface and evidence explicitly describe physical participation, with venue and applicable dates; digital exhibition/catalogue mentions alone do not. A room string alone is retained as location evidence, not automatically proof of display unless its reviewed source semantics explicitly say so.

Create a new artwork for an otherwise unresolved source object. Automatically link only exact institution-scoped accession identity or an explicit artwork Wikidata QID extracted from its identifier field, never any QID mentioned in text. If identifiers disagree with existing mappings, create an identity-conflict record and do not merge. No fuzzy title/artist automatic merging. Provide audited `identity link --object ID --artwork ID --evidence TEXT` and `identity unlink --object ID --evidence TEXT`; unlink creates a separate artwork if needed. History retains artwork_id_at_ingest; queries resolve through current active links. Do not destructively merge/delete artwork rows.

Build the current view from latest successfully extracted observation per source object and venue/assertion scope ordered by observed_at, not ingestion completion time. An explicit unknown on a newly checked page supersedes its earlier positive assertion; a failed fetch does not. A re-extraction of the same response/version replaces only through a supersession link, not fabricated new observation time. On correction/relink, recompute affected projections transactionally.

Expose per-assertion `freshness` (fresh, stale), `validity` (current, future, ended, unspecified), and source evidence. For a consolidated artwork/venue result use fresh currently applicable explicit assertions: disagreement yields `status=conflicted`; no qualifying assertions yields unknown; otherwise preserve the agreed status. Distinct simultaneous venue claims for the same resolved physical artwork also flag conflict rather than picking the newest institution silently. Stale/ended evidence stays in history; ended exhibition dates never fabricate a not_on_display observation. “Currently reported” is explicitly not independent confirmation of physical hanging.

### 7. Serve authenticated read access and operate managed containers
Add `api.py` using FastAPI, `metrics.py`, `Dockerfile` and `deploy/compose.yaml`. The compose file runs only API and worker containers against externally supplied managed PostgreSQL, Hatchet Cloud and S3; no paid provisioning, public website, Redis or embedded database. Run containers non-root with read-only root filesystem and bounded tmpfs for Scrapy children; external TLS termination is required. Secrets come from runtime environment/secrets, never committed files or request logs.

Required environment: DATABASE_URL (TLS required outside tests), HATCHET_CLIENT_TOKEN, S3_BUCKET, S3_REGION, optional S3_ENDPOINT_URL, standard AWS credential chain, NOD_API_TOKEN_SHA256, NOD_CONFIG_PATH; paid credentials only if their tiers are enabled. `nod-engine check-config` validates settings and read-only connectivity and prints missing dependencies without exposing secrets. `nod-engine worker` registers planner/fetch/extract workflows; `nod-engine serve --host 0.0.0.0 --port 8000` starts API. Migrations run once as an explicit deployment command, never automatically at worker boot.

All /v1 and /metrics endpoints require Bearer token comparison against NOD_API_TOKEN_SHA256 using constant-time comparison; no query-string authentication. /health/live returns only process liveness; /health/ready returns 503 until SQL schema and storage connectivity are available, without credentials/details. Support token rotation by restarting with a new hash. API read-only DB role has no budget/admission mutations.

Implement `GET /v1/sources`, `/v1/sources/{id}`, `/v1/artworks`, `/v1/artworks/{id}`, `/v1/artworks/{id}/observations`, `/v1/display`, `/v1/runs/{id}` and `/v1/budgets`. List responses are `{items, next_cursor}` with limit default 50/max 200 and opaque base64url versioned keyset cursor; reject invalid cursors with 400. Artworks supports exact accession/QID and case-insensitive title/artist substring filters; display supports institution_id, venue_id, artwork_id, status and freshness. Detail endpoints return 404 for missing IDs. Dates are ISO8601 UTC; response schema_version=1. Return source URLs, checked times, evidence excerpts, validity/freshness, conflicts and coverage, never raw HTML, credentials or presigned snapshot links.

Add `nod-engine export --kind sources|artworks|observations|display --format jsonl` streaming the same query models without a whole-dataset allocation. Operator reports include oldest overdue source, complete/partial/unknown coverage counts, paused sources, actual/conservative/uncertain spending, request/browser/model/task counts and storage bytes. Prometheus metrics cover overdue age, run outcomes, queue age, reservations and provider errors; avoid raw URL/object ID labels. Emit structured audit/log events on activation, pause, budget denial, price-ceiling breach, drift and reconciliation.

Deployment sequence: check configuration; migrate database; import stopped probe archive; preview and activate selected sources; start API and worker; inspect readiness; enqueue one authorized source; observe epoch/evidence via API before increasing source count. Enable managed PostgreSQL backups/PITR and bucket access restrictions through the operator's existing service controls. Provide `nod-engine verify-storage` to check all referenced object hashes in bounded pages; corruption/missing blobs makes affected evidence unavailable and coverage partial, not silently trustworthy.

## Assumptions and contingencies
- Managed infrastructure is operator-supplied. This plan builds deployable containers and verifies integrations; it does not purchase/provision accounts.
- Daily means desired source-evidence age of 86400 seconds; upstream publishing delays, budget exhaustion, robots restrictions and unknown enumeration sizes prevent guarantees. Report these explicitly rather than weakening safety or pretending full coverage.
- Provider/model IDs, prices, policies and allowed origins come from validated configuration; no configured paid tier means direct/deterministic-only execution with unknown evidence where appropriate.
- If the step-1 implementation uses different internal symbol names, move its actual store/provider/parser callers to the contracts here, retaining behavioral tests; do not add compatibility backends or duplicate fetching logic.
- S3 services lacking conditional PUT/checksum verification are unsupported: fail configuration with `unsupported_object_store`, never silently overwrite evidence.
- No deterministic or reviewed extraction plan for a source means it remains candidate; the engine does not invent a parser or activate all directory seeds automatically.
