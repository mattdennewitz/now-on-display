# Budgeted museum and gallery probe engine

## Context
Build a runnable probe-and-measurement engine, not a production artwork index or scheduled refresh service. Import the institution seeds, discover bounded website surfaces, classify representative templates, measure metadata usefulness and fetch costs, and produce evidence-backed provisional crawl/refresh strategies. The user selected probing first, broad discovery before recurring refresh, and explicitly budgeted Zyte/OpenAI integration.

## Confirmed findings and dependencies
- README.md describes a research archive: 740 museum rows and 758 gallery rows. Root listing and a glob for Python files, dependency manifests, tests, AGENTS.md and compose files found no application implementation to reuse. All engine paths below are new proposed files.
- art-museums.csv headers are Museum Name, City, State / Region, Country, Country Code, Official Website URL, Operating Status.
- us-art-galleries.csv headers are Gallery Name, Size Tier, City & State, Official Website URL.
- museum-research/scope.json requires preserving galleries and not collapsing separately named museums sharing a domain. Leave existing CSVs and research captures unchanged.
- Scrapy's scripting documentation confirms its process runner owns reactor setup: https://docs.scrapy.org/en/latest/topics/practices.html. Use the stable Twisted-backed runner, not experimental reactor-free execution.
- Zyte reference confirms POST https://api.zyte.com/v1/extract, Basic authentication using API key as username and empty password, separate httpResponseBody/httpResponseHeaders versus browserHtml requests: https://docs.zyte.com/zyte-api/usage/reference.html. Do not enable automatic extraction, screenshots or browser actions.
- OpenAI documents Python client.responses.parse(model=..., input=..., text_format=PydanticModel), with explicit handling for refusals, incomplete output and errors: https://developers.openai.com/api/docs/guides/structured-outputs.
- Omeka S documents items and item_sets resources: https://omeka.org/s/docs/developer/api/. IIIF Presentation 3 documents Collection, Manifest, metadata, label and seeAlso, and explicitly warns that presentation metadata does not inherently carry machine-readable semantics: https://iiif.io/api/presentation/3.0/.

## Approach

### 1. Establish a single-host CLI and persisted run contract
Create pyproject.toml with Python >=3.12, package src/now_on_display, console entry nod-probe = now_on_display.cli:main, and dependencies Scrapy, Pydantic 2, OpenAI, httpx, defusedxml and protego; use pytest as the test extra. Resolve and record exact dependency versions in a lock file during implementation. Reuse standard-library argparse, sqlite3, hashlib, csv, json and tomllib. No existing engine utilities exist to reuse.

Create cli.py, models.py, config.py and store.py. Use SQLite WAL with foreign keys, parameterized SQL and schema version 1; refuse newer schema versions. State lives under operator-selected --state, default .probe-state/; keep it and local configuration/credentials out of version control. One OS advisory writer lock per state directory prevents concurrent CLI campaigns; reports may read concurrently. SQLite transactions still protect reservations.

Implement these commands (global --state precedes the subcommand):
- import-seeds --museums art-museums.csv --galleries us-art-galleries.csv: validate both complete inputs before committing, emit imported/unchanged/error counts. Reject missing headers, malformed rows, empty names or non-HTTP(S) website URLs with file/row diagnostics and no partial import. Empty valid files import zero rows.
- sources: emit JSON source IDs, institutions and entry URLs.
- probe --config PATH --campaign NAME --limit N [--source SOURCE_ID ...] [--allow-paid]: require explicit N > 0. New campaign selects sources deterministically, round-robin across museum/gallery types, sorted by ID within type. Continuing the same campaign resumes queued work and never resets budgets. Selected sources/config are frozen; changed config for the same campaign fails. No implicit whole-directory crawl.
- report --campaign NAME --format json|markdown: emit aggregate totals and source strategies; no network.
- reconcile --attempt ID --actual-usd DECIMAL --evidence TEXT: resolve an uncertain paid attempt using an operator-supplied billing record; persist evidence and time. Never silently release uncertain charges.

Use SHA256 of canonical JSON [seed kind, name, original location fields, canonical website URL] as institution ID. Importing identical rows is idempotent; changed identity fields create a new record, without fuzzy merging. Source ID is SHA256 of canonical entry URL; institution_sources is many-to-many, preserving shared-domain institutions. Different entry paths remain separate sources. Canonicalization lowercases scheme/host, strips fragments/default ports, maps empty path to '/', and preserves meaningful path/query bytes; no speculative slash, case or query collapsing.

Persist tables: institutions(id, kind, name, seed_json); sources(id, entry_url); institution_sources; campaigns(id, config_json, config_hash, status, started_at, finished_at); runs(id, campaign_id, source_id, status, stop_reason, timestamps); frontier(run_id, url, kind, discovery_parent, state, family_key); attempts(id, run_id, url, tier, state, reserved_microusd, charged_microusd, charge_basis, provider_request_id, http_status, error, elapsed_ms, bytes, started_at, finished_at); snapshots(hash, relative_path, content_type, bytes); responses(attempt_id, snapshot_hash, final_url, selected_headers_json); classifications(snapshot_hash, input_hash, classifier_version, result_json); strategies(run_id, version, result_json); reconciliations(attempt_id, amount, evidence, timestamp). Add uniqueness for run/source within campaign and run/url/kind frontier entries. JSON result structures use Pydantic and include schema_version=1. Store money in integer micro-USD, parsing decimals without floats and rounding reservations upward.

Run statuses: queued, running, completed, partial, blocked, failed. A completed probe means its bounded sampling plan finished, never complete collection coverage. Exhausted limits produce partial plus a specific stop reason and retained frontier. An inaccessible robots policy produces blocked; internal exceptions produce failed with sanitized diagnostics. Exit 0 for completed/report/import, 2 for invalid input, 3 for partial/blocked/failed campaign outcomes.

### 2. Gate all work and spending before execution
Create budget.py. Configuration is TOML validated before network access, rejecting unknown keys. Required fields: user_agent (must include a contact URL or email), campaign_request_limit, campaign_budget_usd, source_budget_usd. Budgets may be zero. Default per-source caps: 40 total target requests including robots/redirects, 8 sitemap documents, 10,000 retained discovered URLs, 12 families, 3 sampled pages per family, 2 cross-host candidates, 2 paid HTTP calls, 2 paid browser calls, 6 model calls, 600 seconds elapsed, 20 MiB total decoded target bytes. Each response is capped at 2 MiB decoded; model evidence at 12,000 UTF-8 bytes; model output at 1,000 tokens. One target request in flight per exact hostname, minimum 2 seconds between starts or longer robots crawl-delay; process sources sequentially. These are overridable positive configuration values, not claims about optimal site policies.

Paid operations require --allow-paid, appropriate key (ZYTE_API_KEY or OPENAI_API_KEY), and configured price ceilings. OpenAI config requires model, verified maximum input tokens for the full serialized request including schema, max_output_tokens, input/output micro-USD per token, and price_reference. Admit only requests below the configured maximum input byte/token envelope; conservatively reserve the configured maximum input token count plus max output tokens. Require maximum input tokens >= serialized request UTF-8 bytes plus a configured protocol-overhead allowance of at least 4096; reject rather than truncate silently if the model context cannot accommodate this bound. Use normal noncached token rates as ceilings. For Zyte require maximum billable cost per request for each enabled tier and price_reference. Price documentation alone is not an enforced provider cap: expose the budget guarantee as conditional on those ceilings and do not claim universal invoice protection.

Before each network attempt atomically reserve request/paid-call capacity and money against both source and campaign. Denial records budget_deferred and performs no I/O. Direct requests reserve zero provider money but count against requests/bytes/time. Disable SDK and Scrapy automatic retries. At most one explicit retry for direct transport failures or 5xx, only if budget remains; on 429 stop that source with retry_after recorded. No paid automatic retries. HTTP 401/403 are not reasons to bypass restrictions with paid fetching; record blocked/auth_required.

Commit an attempt as in_flight before sending. A response settles OpenAI from reported token usage, or conservatively charges the full reservation when reliable usage is unavailable. Charge Zyte at its configured maximum and label conservative_ceiling unless a verified actual charge is available; never present this as measured invoice cost. Timeouts/crashes after send retain an uncertain reservation. On restart mark old in_flight paid attempts uncertain and do not automatically resend; unrelated queued work can continue. Reconciliation may lower a reservation; an actual cost above its ceiling records the true charge and disables further paid work in that campaign with price_ceiling_breach. Direct abandoned attempts may be requeued under remaining limits. No reservation expires merely because its worker died.

### 3. Discover bounded surfaces with Scrapy
Create crawl.py, urls.py and snapshots.py. Run one Scrapy process per CLI invocation with the normal process runner and Twisted reactor; implement a custom scheduler-facing frontier in SQLite rather than treating JOBDIR as the source of truth. All outgoing direct target requests, robots, redirects and retries pass through the same admission function. Disable automatic redirect/retry/robots middlewares where they bypass accounting; implement explicit bounded robots and redirects using protego and ordinary Scrapy requests. Use streaming byte-limit checks, safe gzip decompression limits, timeouts (20 seconds direct, 90 paid) and maximum 5 redirect hops within the global caps.

Only GET public HTTP(S) URLs. Reject credentials, nonstandard ports other than 80/443, IP literals, and private/loopback/link-local/reserved destinations, including DNS answers and redirects; ensure the address actually connected to is from the validated public DNS result, not a second unchecked resolution. Local test transport is injectable only in test code, never an operator allow-private flag. Strip cookies/auth headers from snapshots and logs. Do not execute scripts, download images/PDFs, submit forms or fetch remote JSON-LD contexts. Browser subrequests are provider-controlled: measure browser calls, not fictitious per-resource politeness guarantees.

Start with robots.txt and entry URL; robots 404 permits discovery, disallow blocks, and network failure/401/403/5xx defers the origin. Respect the configured user agent and crawl-delay. Read declared sitemaps, falling back once to /sitemap.xml if none declared. Parse XML with defusedxml, namespaces, sitemapindex/urlset, gzip support and visited-document cycle detection. Enforce sitemap/document/URL/byte caps during parsing, retaining counts as lower bounds when truncated; never use lastmod as a trusted watermark. Malformed sitemaps are recorded and do not prevent bounded HTML link discovery.

Discover ordinary links and explicit JSON/IIIF/API links in fetched pages. Follow same-origin paths within the entry subtree, plus links from that subtree whose anchor/path indicates collection, artwork/object, exhibition, visit or sitemap; avoid calendar/search query explosions by allowing at most 3 distinct query variants per normalized path. Keep skipped URLs and reasons within the inventory cap. Subdomains and other hosts require an explicit link labeled collection/exhibition/API/IIIF from an admitted page and are capped at 2 candidate origins per source. They must pass their own robots/security gates and inherit the source budget; external redirects not meeting this rule are recorded but not followed. Shared host throttling remains global across sources.

Persist decoded bodies by SHA256 using atomic temporary-file rename; store UTC fetch time, final URL, status, ETag/Last-Modified/Content-Type and latency separately. Never conflate identical content with a new fetch time. Failed/incomplete bodies cannot become successful evidence. On resumed runs use existing successful snapshots; an explicitly new campaign refetches and can compare hashes without assuming unchanged unrelated pages.

### 4. Group URLs and classify sampled evidence
Create discovery.py, adapters.py and classify.py. A family key is origin + path with all-decimal and UUID segments replaced by tokens + sorted query-key names. Do not collapse arbitrary slugs. Where a parent listing supplies >=3 sibling links of equal path depth under one parent, additionally group their final slug under that parent as a candidate family; persist membership provenance. Grouping suggests sampling, never proves uniformity.

Prioritize one sample from each family before second/third samples. Reserve 3 of 12 family slots for otherwise unrecognized families, selected by SHA256(source_id + URL) ordering; use the remaining slots for collection/exhibition/object/visit candidates. Within a family select the 3 lowest distinct URL hashes; count fewer available samples honestly. URL-only labels remain provisional. On conflicting sample labels, mark family mixed and retain per-page results; do not generalize a single label. No LLM sees an entire sitemap.

Implement convention detectors for Omeka S and IIIF Presentation 3 plus generic JSON-LD/HTML. These are real initial adapters, not empty interfaces for imagined platforms. Omeka detection requires o: namespace context or explicit Omeka S generator plus an observed API link; parse observed items/item_sets payloads and identifiers, without guessing API installation roots. IIIF requires its presentation context and Collection/Manifest type; read label, metadata, items and seeAlso but never infer on-display status from digital presentation. Generic parsing extracts JSON-LD types, Event dates, physical Place fields, accession/identifier labels, headings, repeated artwork links and next-page links with evidence paths. Ambiguous semantics remain unknown. Future proprietary platforms use the generic/model path rather than fabricated fingerprints.

PageType literals: collection_index, object_detail, exhibition_index, exhibition_detail, visit_location, other, unknown. Classification contains page_type; method (adapter, heuristic, model); adapter/version; evidence[] with field, exact quote, location (JSON pointer or DOM selector); evidence_fields[] drawn from explicit_display_status, physical_location, exhibition_dates, identified_artworks, stable_object_identifiers, pagination_or_object_links; and linked_candidate_urls[]. Presence is evidence of a field, not a claim a work is presently displayed. Multiple incompatible deterministic classifications produce unknown and qualify for model review. URL words alone never produce confirmed page_type.

Use OpenAI structured output only on unresolved sampled pages. Input is bounded cleaned text with numbered blocks, title/headings, observed links and extracted structured fields; treat it as untrusted data, prohibit tools and code generation, and state that digital exhibitions, online availability and collection ownership are not physical display. Returned quotations must match an input block; linked URLs must be among supplied observed URLs. Invalid references, refusal, incomplete output or API failure produce unknown with reason and no automatic stronger-model escalation. Avoid numerical model confidence as an authority signal.

Cache successful classifications by canonical bounded input hash + model + prompt/schema/adapter versions. Validate cache references against the current snapshot. Record truncation; a truncated sample cannot support an assertion that metadata is absent. Use the model to propose labels and evidence, not executable selectors or network actions. Applying agreement across a family yields a provisional rule with sample counts, never an automatic production crawl approval.

### 5. Integrate opt-in paid fetching and evidence-backed recommendations
Create providers.py and strategy.py. Implement Zyte via httpx with retries disabled: HTTP tier requests httpResponseBody=true and httpResponseHeaders=true and base64-decodes the body; browser tier requests browserHtml=true. Apply the same target URL/robots/budget admission before either call. Reserve before dispatch; persist sanitized provider identifiers and HTTP status. SDK credentials are never stored. Cap provider response envelopes as well as decoded bodies.

Allow paid HTTP only when direct transport/5xx failures exhausted their allowed retry, not on robots/auth/rate-limit blocks. Allow a browser sample only for successful HTML with <200 normalized visible text characters plus a script-bearing application root (#root, #app or #__next), or explicit noscript text requiring JavaScript. Every escalation must fit per-tier caps and --allow-paid. Blank results after the allowed tier are unresolved, not a reason to escalate again. No screenshots or paid auto-extraction. A source may have different tiers for different families.

Produce append-only strategy version 1 per run, including entry points/origins, per-family sample URLs and evidence references, platform candidates, fetchability, discoverability, metadata fields, unresolved questions, observed request/error/latency/byte totals, spending breakdown (actual, conservative, uncertain), budget remaining, and capped/skipped inventory counts. All dimensions are independent; avoid a single opaque score.

Recommendation enum and ordered selection: structured_candidate if sampled structured data contains explicit display/location evidence; exhibition_candidate if exhibition samples contain dates and identified artwork evidence; object_pages_candidate if object pages contain display/location evidence; manual_review otherwise. This precedence only selects the headline; preserve all useful surfaces and separate source/family recommendations. Add paused_cost or blocked_access reasons independently, without erasing evidence.

For each surface report proposed refresh coverage (feed pages, listing plus detail pages, individual object pages, or unknown). observed_refresh_unit_cost is the sampled request/extraction cost with basis; estimated_full_refresh_cost is null unless a trustworthy enumerated count and applicable sampled tier permit a clearly labeled extrapolation. Treat capped sitemap counts as lower bounds. Report update_frequency=unknown, change_signal_reliability=unverified and collection_coverage=unverified for initial probes. A homepage hash, sitemap timestamp, IIIF manifest or missing display field cannot establish physical location or full coverage. The report suggests an explicitly configurable 24-hour freshness target for later admission costing, but creates no scheduled jobs.

## Verification
From repository root use Python 3.12+ and a new virtual environment: `python3 -m venv .venv`, `.venv/bin/python -m pip install -e '.[test]'`, then `.venv/bin/python -m pytest tests/probe -q`. The test suite uses temporary SQLite/snapshot directories, a local fixture HTTP server through a test-only transport, and scripted provider responses; never external network or paid keys. Add consumer-visible regression tests in tests/probe/test_budget.py, test_discovery.py, test_classification.py and test_cli.py, sharing fixtures in conftest.py.

Required acceptance scenarios:
1. Two named institutions on one domain and identical reimports preserve two identities without duplicate import rows; malformed input leaves the database unchanged.
2. Fixture site has robots disallow, recursive sitemap index, duplicate URLs, gzip expansion beyond cap, collection objects, an exhibition with no works, another with works/dates, a JS shell, an external collection link and unrelated external links. The actual CLI stops at bounds, never fetches disallowed/unrelated targets, preserves unknowns and produces distinct collection/exhibition evidence. Page identity without explicit display text never becomes on-display evidence.
3. Budget of 100 micro-USD with two simultaneous 70-micro-USD reservations admits exactly one; a timeout retains 70 reserved after restart; reconciliation to 40 releases only 30. A second CLI cannot acquire the same writer lock. Unknown paid outcomes never silently retry or reset source/campaign allowances.
4. HTTP 429/403 and robots outage never trigger a paid bypass. JS shell only uses the configured browser allowance. Each explicit retry/redirect consumes another request slot. Oversized/malformed provider responses are accounted for and yield unknown, not false success.
5. Model quotations absent from input and invented URLs are rejected. A rich object description without physical-display evidence cannot qualify for structured_candidate. IIIF Collection is not evidence of an on-site exhibition. Conflicting family samples stay mixed; unusual paths receive reserved exploration samples. Model refusals do not invoke a bigger model.
6. Kill a subprocess after snapshot commit and before classification; resume the same campaign without refetching its completed URL. Change configuration and verify resume fails. New campaign creates a new dated run and does not mutate prior strategy evidence.
7. Redirect/DNS destination tests deny loopback/private targets before connecting. Fixture-only transport is unavailable from CLI configuration.
8. Launch CLI end-to-end in test_cli.py with the actual subprocess entry point, import fixture seeds, run a bounded campaign, then render both report formats. Assert report URLs/evidence/cost basis/stop reasons against the fixture server's received-request log. This is the visual/CLI surface proof, not merely testing internal methods.

Finally perform a no-network real-data smoke: `.venv/bin/nod-probe --state /tmp/nod-probe-smoke import-seeds --museums art-museums.csv --galleries us-art-galleries.csv`, then `.venv/bin/nod-probe --state /tmp/nod-probe-smoke sources`; confirm 740 museum and 758 gallery institution records from this checkout, preserving distinct institutions when sources share hosts. If input files have legitimately changed, compare against parsed CSV row counts rather than hard-coded counts. Do not run a public or paid campaign without operator-configured contact identity, source limit and spending ceilings. Provider tests prove client contracts and accounting; without authorized live credentials, explicitly report real-provider behavior and model accuracy as unverified.

## Assumptions and contingencies
- The selected deliverable is a probe engine. SQLite and a CLI deliberately replace Hatchet/PostgreSQL at this stage; production indexing, artwork identity merging and scheduling are not implemented by this plan.
- Paid provider keys, model IDs and prices are supplied at runtime, never invented. Without them the same engine runs deterministic direct-only probes and records unresolved classifications/tiers; it does not pretend paid integrations succeeded.
- Museum software conventions begin with verified Omeka S, IIIF and generic structured/HTML rules. Unknown/proprietary deployments remain candidates for model-assisted sampling, not unsupported claims of platform compatibility.
- Budget enforcement bounds admitted operations against configured provider ceilings, not total cloud compute, provider-internal browser subrequests or unknown billing policies. If a ceiling cannot be established, disable that paid tier and report the missing ceiling.
- Live probing may discover no useful evidence or only blocked sites. Successful implementation preserves that result with evidence and stop reasons rather than fabricating extraction or completeness.
