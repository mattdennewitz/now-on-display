# Budgeted museum and gallery probe engine

## Context
The first deliverable is an offline, reproducible comparison of two bounded direct-fetch policies: does sitemap/family discovery find more trustworthy evidence of physical display than following explicit links at the same request cap? Use the result to decide whether to invest in discovery, interpretation, or manual review. It is not an artwork index, live crawl, paid integration, or refresh service.

## Confirmed findings and dependencies
- README.md describes a research archive: 740 museum rows and 758 gallery rows. Root listing and a glob for Python files, dependency manifests, tests, AGENTS.md and compose files found no application implementation to reuse. All engine paths below are new proposed files.
- art-museums.csv headers are Museum Name, City, State / Region, Country, Country Code, Official Website URL, Operating Status.
- us-art-galleries.csv headers are Gallery Name, Size Tier, City & State, Official Website URL.
- museum-research/scope.json requires preserving galleries and not collapsing separately named museums sharing a domain. Leave existing CSVs and research captures unchanged.
- Scrapy's scripting documentation confirms its process runner owns reactor setup: https://docs.scrapy.org/en/latest/topics/practices.html. Use the stable Twisted-backed runner, not experimental reactor-free execution.
- Zyte reference confirms POST https://api.zyte.com/v1/extract, Basic authentication using API key as username and empty password, separate httpResponseBody/httpResponseHeaders versus browserHtml requests: https://docs.zyte.com/zyte-api/usage/reference.html. Do not enable automatic extraction, screenshots or browser actions.
- OpenAI documents Python client.responses.parse(model=..., input=..., text_format=PydanticModel), with explicit handling for refusals, incomplete output and errors: https://developers.openai.com/api/docs/guides/structured-outputs.
- Omeka S documents items and item_sets resources: https://omeka.org/s/docs/developer/api/. IIIF Presentation 3 documents Collection, Manifest, metadata, label and seeAlso, and explicitly warns that presentation metadata does not inherently carry machine-readable semantics: https://iiif.io/api/presentation/3.0/.

## Approach

### 0. Run the offline decision experiment first

**Freeze the cohort and archive.** Start with 24 institutions: 12 museums and 12 galleries, targeting 4 of each for development and 8 of each for holdout. Use a recorded seed and stratify museums by available country/region labels and galleries by size tier; retain missing strata as unknown. Keep institutions sharing a hostname or known template family on the same side of the split, and report any split imbalance. Freeze institution IDs, source IDs, entry URLs and group assignments before tuning. Fetch each canonical source once per policy, but credit a claim to an institution only when the evidence identifies it; report ambiguous attribution as source-only. Publish institution, source and host counts by split and institution kind, including blocked, unreviewable and unresolved entries. This pilot does not estimate archive-wide yield.

Use existing permitted captures where they qualify. Store a versioned replay manifest: request URL, observed capture time, response status and relevant headers (including Location), decoded body hash and bytes, and capture provenance. Preserve robots, redirects and failures as responses, not just successful pages. A request not in the archive is an archive miss, never an inferred 404 or a live fallback. Existing research HTML candidates are not yet a verified linked corpus. Record gaps without silently replacing selected institutions. Synthetic linked sites can prove mechanics but cannot substitute for holdout data; if a linked archive is insufficient, report the missing captures and do not draw a comparative conclusion until a suitable corpus is available. Public collection of additional captures needs separate authorization.

**Build a reference inventory.** Two reviewers independently traverse archived links from each entry under a recorded review budget (default 30 minutes per institution), then adjudicate page and claim labels. Record useful URLs, the supported artwork or exhibition, asserting institution, physical venue if known, assertion polarity/type, applicable dates if stated, quote and locator, and ambiguity. Include present, past, future, online-only, contradictory and site-address-only examples in the rubric and fixtures. Distinguish “reviewers found none in the reviewed inventory” from “not reviewable.” Freeze the adjudicated holdout before policy tuning; the runner must not read those labels when generating requests or claims. Recall is against the reviewed inventory, not the entire site.

**Compare two policies.** Run `nod-probe replay --corpus PATH --config PATH --format json|markdown` against the same immutable captures with direct requests only, a separate disposable state directory per arm, identical classifiers and admission rules, and the same 40-request and 20 MiB decoded-byte ceilings per source. Set any aggregate caps high enough that they do not cut off the cohort. Simulate deadlines and cooldowns with a deterministic replay clock, not wall time. Debit robots, redirects, retries and archive misses against the request cap; report actual usage as well as the cap. No arm may use the other's fetched results or cooldowns.

- **Link-first baseline:** Read robots and the entry page, then follow eligible links explicitly labeled collection, exhibition, artwork/object or an associated API/IIIF surface, breadth-first in canonical URL order. Classify eligible fetched pages. No sitemap discovery or family grouping.
- **Sitemap plus families:** Use the bounded sitemap/link inventory in §3 and the frozen family selection in §4. Within the same 40-request cap, reserve 12 request slots for selected sample work; stop inventory requests before consuming that reserve. Read one page per chosen family before second or third samples. Charge redirects/retries to the phase that initiated them; the reserve is a request allowance, not a promise of 12 successful pages.

**Report and decide.** For reviewed useful pages, show cumulative counts discovered, selected, fetched and correctly interpreted, plus archive misses, access/budget denials, and label misses at the stage where they first occur. Show supported claims and credited institutions, unsupported positive claims, requests/bytes per credited institution (null when none), and the request index of the first supported claim. For the primary yield metric, credit an institution only for a supported assertion that a work was physically on view at capture, not a historical/future mention or a generic venue address. Adjudicate new positive assertions outside the reference inventory against the archived evidence, without revealing the policy that produced them.

Freeze the decision rule before opening holdout results. An arm with any unsupported positive display claim on adjudicated cases is not eligible for adoption. Adopt sitemap plus families only if it is eligible, credits at least two held-out institutions the baseline did not, and loses none credited by the baseline within the matched caps; otherwise retain the baseline if it is eligible, or adopt neither. If archive gaps could change the decision, mark it inconclusive. Report paired results, not a population estimate. Use the first missed stage to choose between improving discovery, improving interpretation, and leaving the surface to manual review. Do not select a policy by run completion rate.

**Milestone order.** Deliver the claim rubric, replay corpus manifest, deterministic direct-only runner, and matched report first. Sections 1–5 specify the engine contracts; defer public-campaign plumbing that the replay does not exercise until there is an authorized public evaluation. Do not wire paid dispatch, paid-only schema/CLI or SDK dependencies into the first milestone. §6 retains the mandatory paid-mode contracts for a later, separately authorized milestone; §5 describes the evidence required before a refresh study.

### 1. Establish a single-host CLI and persisted run contract
Create pyproject.toml with Python >=3.12, package src/now_on_display, console entry nod-probe = now_on_display.cli:main, and dependencies Scrapy, Pydantic 2, defusedxml and protego; use pytest as the test extra. Add OpenAI or httpx only when implementing its paid integration in §6. Resolve and record exact dependency versions in a lock file during implementation. Reuse standard-library argparse, sqlite3, hashlib, csv, json and tomllib.

Create cli.py, models.py, config.py and store.py. Use SQLite WAL with foreign keys, parameterized SQL and schema version 1; refuse newer schema versions. State lives under operator-selected --state, default .probe-state/; keep it and local configuration/credentials out of version control. One OS advisory writer lock per state directory prevents concurrent CLI campaigns; reports may read concurrently. SQLite transactions still protect reservations.

Implement `replay` as specified in §0. Also define these commands (global --state precedes the subcommand); add `probe` only for the authorized public milestone and `reconcile` only for the paid milestone:
- import-seeds --museums art-museums.csv --galleries us-art-galleries.csv: validate both complete inputs before committing, emit imported/unchanged/error counts. Reject missing headers, malformed rows, empty names or non-HTTP(S) website URLs with file/row diagnostics and no partial import. Empty valid files import zero rows.
- sources: emit JSON source IDs, institutions and entry URLs.
- probe --config PATH --campaign NAME --limit N [--source SOURCE_ID ...] [--allow-paid]: require explicit N > 0. New campaign selects sources deterministically, round-robin across museum/gallery types, sorted by ID within type. Continuing the same campaign resumes queued work and never resets budgets. Selected sources/config are frozen; changed config for the same campaign fails. No implicit whole-directory crawl.
- report --campaign NAME --format json|markdown: emit aggregate totals and source strategies; no network.
- reconcile --attempt ID --actual-usd DECIMAL --evidence TEXT: settle the billing of an uncertain paid attempt using an operator-supplied record; persist evidence and time. Never silently release uncertain charges or turn a billing reconciliation into a recovered result.

Use SHA256 of canonical JSON [seed kind, name, original location fields, canonical website URL] as institution ID. Importing identical rows is idempotent; changed identity fields create a new record, without fuzzy merging. Source ID is SHA256 of canonical entry URL; institution_sources is many-to-many, preserving shared-domain institutions. Different entry paths remain separate sources. Canonicalization lowercases scheme/host, strips fragments/default ports, maps empty path to '/', and preserves meaningful path/query bytes; no speculative slash, case or query collapsing.

Persist tables: institutions(id, kind, name, seed_json); sources(id, entry_url); institution_sources; campaigns(id, config_json, config_hash, status, started_at, finished_at); runs(id, campaign_id, source_id, status, stop_reason, sample_frozen_at, timestamps); frontier(run_id, url, kind, discovery_parent, state, family_key); samples(run_id, url, family_key, sample_order); host_cooldowns(hostname, not_before_utc); attempts(id, run_id, url, tier, state, http_status, error, elapsed_ms, bytes, started_at, finished_at); snapshots(hash, relative_path, content_type, bytes); responses(attempt_id, snapshot_hash, final_url, selected_headers_json); classifications(snapshot_hash, input_hash, classifier_version, result_json); strategies(run_id, version, result_json). Add uniqueness for run/source within campaign, run/url/kind frontier entries, run/url sample entries and hostname cooldowns. Use a separate campaign namespace per replay arm. JSON result structures use Pydantic and include schema_version=1.

For the paid milestone, add paid_operation_key (unique when non-null), reserved_microusd, charged_microusd, charge_basis and provider_request_id to attempts, and add reconciliations(attempt_id, amount, evidence, timestamp). Store money in integer micro-USD, parsing decimals without floats and rounding reservations upward.

Run statuses: queued, running, completed, partial, blocked, failed. A completed probe finished its bounded discovery and processed every selected sample, even if some processed results are unknown. It does not imply complete collection coverage. Planned discovery and sampling cutoffs are inventory truncation or skips, not partial by themselves. Report partial with a specific stop reason and retained frontier when admission limits interrupt required discovery or leave selected work outstanding. Denial of an individual path does not block the entire origin; report blocked for a source only when access policy prevents required work and no admitted route remains. Internal exceptions produce failed with sanitized diagnostics. Exit 0 for completed/report/import, 2 for invalid input, 3 for partial/blocked/failed campaign outcomes.

### 2. Gate all work and spending before execution
Create budget.py. Validate TOML before execution, rejecting unknown keys. Require user_agent (with contact URL or email) and campaign_request_limit. Add campaign_budget_usd and source_budget_usd in paid mode; they may be zero. Default per-source caps: 40 total target requests including robots/redirects, 8 sitemap documents, 10,000 retained discovered URLs, 12 families, 3 sampled pages per family, 2 cross-host candidates, 600 seconds elapsed, 20 MiB total decoded target bytes, and 2 MiB decoded per response. One target request in flight per exact hostname, minimum 2 seconds between starts or longer robots crawl-delay; process sources sequentially. The later paid defaults are 2 HTTP calls, 2 browser calls, 6 model calls, 12,000 UTF-8 bytes of model evidence and 1,000 output tokens. These are overridable positive caps, not claims about optimal site policies; freeze the chosen caps for the comparison.

Paid operations require --allow-paid, appropriate key (ZYTE_API_KEY or OPENAI_API_KEY), and configured price ceilings. OpenAI config requires model, verified maximum input tokens for the full serialized request including schema, max_output_tokens, input/output micro-USD per token, and price_reference. Admit only requests below the configured maximum input byte/token envelope; conservatively reserve the configured maximum input token count plus max output tokens. Require maximum input tokens >= serialized request UTF-8 bytes plus a configured protocol-overhead allowance of at least 4096; reject rather than truncate silently if the model context cannot accommodate this bound. Use normal noncached token rates as ceilings. For Zyte require maximum billable cost per request for each enabled tier and price_reference. Price documentation alone is not an enforced provider cap: expose the budget guarantee as conditional on those ceilings and do not claim universal invoice protection.

Before each target attempt atomically reserve request capacity against source and campaign, including in replay. In paid mode also reserve applicable paid-call capacity and money. Budget denial records budget_deferred and performs no I/O. Direct requests count against requests/bytes/time, not provider money. Disable Scrapy and SDK automatic retries. Allow at most one explicit retry for direct transport failures or 5xx, only if budget remains, and do not retry archive misses. No paid automatic retries. HTTP 401/403 are not reasons to bypass restrictions with paid fetching; record blocked/auth_required.

On a target 429, stop that source and atomically record the outcome and a cooldown keyed by the canonical hostname, shared across sources and campaigns in the state directory. Parse Retry-After as delta seconds or an HTTP date; if missing or invalid use a 60-second fallback. Never shorten an existing deadline. Consult the stored UTC not-before time before admitting every target request, including robots, redirects, retries and the initial target of a paid call. Before the deadline, defer that hostname without consuming a request slot or doing I/O; keep unrelated hosts eligible, including after restart.

For paid work, derive a logical operation key before dispatch. For a fetch use run, canonical target URL and tier; for a model classification use run, response ID (the fetch attempt ID), canonical bounded-input hash and classifier version (including model, prompt, schema and adapter versions). The same transaction uniquely claims the key, reserves capacity and money, and commits the attempt as in_flight. For direct work commit an in_flight attempt before sending as well.

A response settles OpenAI from reported token usage, or conservatively charges the full reservation when reliable usage is unavailable. Persist the model outcome with settlement so a committed attempt cannot disappear from classification on resume. Charge Zyte at its configured maximum and label conservative_ceiling unless a verified actual charge is available; never present this as measured invoice cost. Timeouts/crashes after send retain an uncertain reservation. On restart mark old in_flight paid attempts uncertain, block replay by operation key and keep unrelated work eligible. Represent a missing classification as unknown with an uncertain-outcome reason, not a successful cache entry. Reconciliation may lower the reservation but does not recover the missing result or authorize a resend. An actual cost above its ceiling records the true charge and disables further paid work in that campaign with price_ceiling_breach. Direct abandoned attempts may be requeued under remaining limits. No reservation expires merely because its worker died.

### 3. Discover bounded surfaces with Scrapy
Create crawl.py, urls.py and snapshots.py. Run one Scrapy process per CLI invocation with the normal process runner and Twisted reactor; implement a custom scheduler-facing frontier in SQLite rather than treating JOBDIR as the source of truth. All outgoing direct target requests, robots, redirects and retries pass through the same admission function. Disable automatic redirect/retry/robots middlewares where they bypass accounting; implement explicit bounded robots and redirects using protego and ordinary Scrapy requests. Use streaming byte-limit checks, safe gzip decompression limits, timeouts (20 seconds direct, 90 paid) and maximum 5 redirect hops within the global caps.

Replay uses the same URL/origin, robots, cooldown and budget rules as the direct path, with a read-only archive transport and a deterministic clock. Supply only the current URL's recorded response on request. No DNS lookups, provider credentials, or outbound connections; archive replay provides no evidence that live DNS pinning works. The archive transport never writes to a public campaign's state.

For direct requests, only GET public HTTP(S) URLs. Reject credentials, nonstandard ports other than 80/443, IP literals, and private/loopback/link-local/reserved destinations, including DNS answers and redirects; ensure the address actually connected to is from the validated public DNS result, not a second unchecked resolution. Local test transport is injectable only in test code, never an operator allow-private flag. Strip cookies/auth headers from snapshots and logs. Direct fetching and parsing do not execute scripts, download images/PDFs, submit forms or fetch remote JSON-LD contexts. Paid transports have separate enforcement requirements in §6.

Start with robots.txt and the entry URL. Robots 404 permits discovery; a disallow denies the matching path without denying permitted paths, and network failure/401/403/5xx makes the origin policy unavailable. Record path denial and origin-policy unavailability separately. Respect the configured user agent and crawl-delay. In the sitemap arm, read permitted declared sitemaps, falling back once to /sitemap.xml if none are declared. Parse XML with defusedxml, namespaces, sitemapindex/urlset, gzip support and visited-document cycle detection. Enforce sitemap/document/URL/byte caps during parsing, retaining counts as lower bounds when truncated; never use lastmod as a trusted watermark. Malformed sitemaps are recorded and do not prevent bounded HTML link discovery.

Discover ordinary links and explicit JSON/IIIF/API links in fetched pages. Follow same-origin paths within the entry subtree, plus links from that subtree whose anchor/path indicates collection, artwork/object, exhibition, visit or sitemap; avoid calendar/search query explosions by allowing at most 3 distinct query variants per normalized path. Keep skipped URLs and reasons within the inventory cap. Subdomains and other hosts require an explicit link labeled collection/exhibition/API/IIIF from an admitted page and are capped at 2 candidate origins per source. They must pass their own robots/security gates and inherit the source budget; external redirects not meeting this rule are recorded but not followed. Shared host throttling remains global across sources.

Persist decoded bodies by SHA256 using atomic temporary-file rename; store UTC fetch time, final URL, status, ETag/Last-Modified/Content-Type and latency separately. Never conflate identical content with a new fetch time. Failed/incomplete bodies cannot become successful evidence. On resumed runs use existing successful snapshots; an explicitly new campaign refetches and can compare hashes without assuming unchanged unrelated pages.

### 4. Group URLs and classify sampled evidence
Create discovery.py, adapters.py and classify.py. A family key is origin + path with all-decimal and UUID segments replaced by tokens + sorted query-key names. Do not collapse arbitrary slugs. Where a parent listing supplies >=3 sibling links of equal path depth under one parent, additionally group their final slug under that parent as a candidate family; persist membership provenance. Grouping suggests sampling, never proves uniformity.

After bounded discovery, persist the ordered sample set in one transaction and reuse it unchanged on resume. Prioritize one sample from each selected family before second/third samples. Reserve 3 of 12 family slots for otherwise unrecognized families, selected by SHA256(source_id + URL) ordering; use the remaining slots for collection/exhibition/object/visit candidates. Within a family select the 3 lowest distinct URL hashes; count fewer available samples honestly. Reuse eligible responses obtained during discovery and record unsampled families and URLs as inventory skips, not pending work. URL-only labels remain provisional. On conflicting sample labels, mark family mixed and retain per-page results; do not generalize a single label. No LLM sees an entire sitemap.

Implement convention detectors for Omeka S and IIIF Presentation 3 plus generic JSON-LD/HTML. These are real initial adapters, not empty interfaces for imagined platforms. Omeka detection requires o: namespace context or explicit Omeka S generator plus an observed API link; parse observed items/item_sets payloads and identifiers, without guessing API installation roots. IIIF requires its presentation context and Collection/Manifest type; read label, metadata, items and seeAlso but never infer on-display status from digital presentation. Generic parsing extracts JSON-LD types, Event dates, physical Place fields, accession/identifier labels, headings, repeated artwork links and next-page links with evidence paths. Ambiguous semantics remain unknown. Future proprietary platforms use the generic/model path rather than fabricated fingerprints.

PageType literals: collection_index, object_detail, exhibition_index, exhibition_detail, visit_location, other, unknown. Classification contains page_type; method (adapter, heuristic, model); adapter/version; evidence[] with field, exact quote, location (JSON pointer or DOM selector); evidence_fields[] drawn from explicit_display_status, physical_location, exhibition_dates, identified_artworks, stable_object_identifiers, pagination_or_object_links; and linked_candidate_urls[]. A display or physical-location assertion also carries a subject reference to the artwork or exhibition in the snapshot. Require the relationship in the same structured record or in explicit text; a quote and locator alone do not prove it. Retain site-level addresses or Place records as visit evidence only. Presence is evidence of a field, not a claim a work is presently displayed. Multiple incompatible deterministic classifications produce unknown and qualify for model review. URL words alone never produce confirmed page_type.

In the later model milestone, use OpenAI structured output only on unresolved sampled pages. Input is bounded cleaned text with numbered blocks, title/headings, observed links and extracted structured fields; treat it as untrusted data, prohibit tools and code generation, and state that digital exhibitions, online availability and collection ownership are not physical display. Returned quotations must match an input block; linked URLs must be among supplied observed URLs. Keep model-only subject relationships as review candidates until a deterministic rule or a human independently confirms the binding. Report incremental accepted claims on the unresolved subset separately from adapter results. Invalid references, refusal, incomplete output or API failure produce unknown with reason and no automatic stronger-model escalation. Avoid numerical model confidence as an authority signal.

Cache successful classifications by canonical bounded input hash + model + prompt/schema/adapter versions. Validate cache references against the current snapshot. Record truncation; a truncated sample cannot support an assertion that metadata is absent. Use the model to propose labels and evidence, not executable selectors or network actions. Applying agreement across a family yields a provisional rule with sample counts, never an automatic production crawl approval.

### 5. Report claims, acquisition routes and observed probe cost

Create strategy.py. Report two independent outputs:

- **Observed institutional claims:** For each cited assertion retain the subject and asserting institution (or source-only attribution), venue if stated, assertion type (e.g. on view, not on view, included in an exhibition), applicable dates if stated, observation time, evidence locator, and any conflicting assertions. As of the report's observation date, distinguish past, active, future and unknown applicability; an undated “on view” describes what the publisher said at capture, not how long it remains valid or independently verified real-world status. An ended exhibition with named works can be useful historical evidence but does not establish current display. Online-only evidence and generic site addresses cannot establish a physical display claim.
- **Acquisition routes:** List potentially useful feeds, exhibition/listing plus detail pages, and individual object pages independently, with the fields each route supports, evidence references, sample counts, and access/cost reasons. No forced platform ranking, and no structured-data bonus merely for serialization. An institution may have multiple useful routes or none; preserve manual review where binding or applicability is unresolved.

Produce append-only, as-of strategy records per run, including entry points/origins, per-family samples, fetchability, discoverability, unresolved questions, request/error/latency/byte totals, capped/skipped inventory and observed probe cost. Separate discovery cost from evidence acquisition, identify the denominator, and label archive replay requests/bytes as replay measurements, not observed network latency or invoice costs. In paid mode keep historical cost basis immutable and render current settlement and remaining budget separately from the ledger.

Report proposed revisit units, not refresh cost or cadence, from the first observation. Full-refresh cost, update frequency and change-signal reliability remain unknown; collection coverage remains unverified. A separate authorized revisit study must observe subject-level claim changes on the same surfaces and distinguish claim changes from markup churn. Before extrapolating, require an enumerated population, applicable fetch mix, and explicit accounting for shared listing and one-time discovery work. Freshness targets are operator-specified scenarios, not a default recommendation. No scheduler.

### 6. Later milestone: opt-in paid operations
Create providers.py for this later milestone. Implement Zyte via httpx with client retries disabled. The HTTP tier sends `httpResponseBody: true`, `httpResponseHeaders: true` and `followRedirect: false`, then base64-decodes the body when applicable. [Zyte HTTP follows redirects by default](https://docs.zyte.com/zyte-api/usage/http.html#redirection). On a redirect, validate the target's Location and run each next hop through destination, origin, robots, cooldown and budget admission before reserving and sending a new request. The [Zyte API reference](https://docs.zyte.com/zyte-api/usage/reference.html#operation/extract/request/followRedirect) limits `followRedirect` to HTTP; `browserHtml` follows redirects and the browser's subrequests are provider-controlled.

Apply local target URL, robots, cooldown and budget admission before either paid tier, but do not treat it as an enforcement guarantee: local DNS validation cannot pin a provider's connection. Keep each paid fetch tier disabled unless its provider contract and configuration enforce the required destination policy before every connection, including redirects and browser subrequests where applicable. No post-fetch final-URL check or `--allow-paid` override can substitute for that enforcement. Report unavailable enforcement as the reason the tier was not admitted. Count billable browser calls, not internal resource requests. Reserve before dispatch; persist sanitized provider identifiers and HTTP status. SDK credentials are never stored. Cap provider response envelopes as well as decoded bodies.

Allow paid HTTP only when direct transport/5xx failures exhausted their allowed retry, not on robots/auth/rate-limit blocks. Allow a browser sample only for successful HTML with <200 normalized visible text characters plus a script-bearing application root (#root, #app or #__next), or explicit noscript text requiring JavaScript. Every escalation must fit per-tier caps and --allow-paid. Blank results after the allowed tier are unresolved, not a reason to escalate again. No screenshots or paid auto-extraction. A source may have different tiers for different families.

From repository root use Python 3.12+ and a new virtual environment: `python3 -m venv .venv`, `.venv/bin/python -m pip install -e '.[test]'`, then `.venv/bin/python -m pytest tests/probe -q`. Use temporary SQLite/snapshot directories, archived/synthetic linked sites and a local fixture HTTP server through a test-only transport. Later paid tests use scripted responses; tests never reach the external network or use paid keys. Add consumer-visible regression tests in tests/probe/test_budget.py, test_discovery.py, test_classification.py and test_cli.py, sharing fixtures in conftest.py.

Required acceptance scenarios:
1. Two named institutions on one domain and identical reimports preserve two identities without duplicate import rows; malformed input leaves the database unchanged.
2. Fixture site has robots disallow, recursive sitemap index, duplicate URLs, gzip expansion beyond cap, collection objects, an exhibition with no works, another with works/dates, a JS shell, an external collection link and unrelated external links. The actual CLI stops at bounds, never fetches disallowed/unrelated targets, preserves unknowns and produces distinct collection/exhibition evidence. Page identity without explicit display text never becomes on-display evidence.
3. A second CLI cannot acquire the same writer lock. In the paid milestone, a budget of 100 micro-USD with two simultaneous 70-micro-USD reservations admits exactly one; a timeout retains 70 reserved after restart; reconciliation to 40 releases only 30. Unknown paid outcomes never silently retry or reset source/campaign allowances.
4. After source A receives a 429, restart and attempt source B on the same hostname: its request log stays empty until Retry-After expires, but another host proceeds. Each explicit retry/redirect consumes another request slot. In the paid milestone, 429/403 and robots outage never trigger a paid bypass, a JS shell cannot trigger browser rendering without provider destination enforcement, and oversized/malformed responses are accounted for and yield unknown, not false success.
5. An object with only a footer address gets no physical-display claim; adding an explicit “on view in Gallery 4” bound to the object yields an institutional claim and a useful detail-page route. An ended exhibition with named works remains a historical route, not current-display evidence. IIIF Collection is not evidence of an on-site exhibition. Conflicting family samples stay mixed; unusual paths receive reserved exploration samples. In the paid model milestone, absent quotations and invented URLs are rejected and refusals do not invoke a bigger model.
6. Kill a subprocess after snapshot commit and before classification; resume the same campaign without refetching its completed URL. Change configuration and verify resume fails. New campaign creates a new dated run and does not mutate prior strategy evidence.
7. Redirect/DNS destination tests deny loopback/private targets before connecting. In the paid milestone, a scripted paid HTTP request carries `followRedirect: false`; a 302 to an unapproved host leaves no second call in the provider request log. Fixture-only transport and provider capabilities are unavailable from public CLI configuration.
8. Launch the actual CLI subprocess, import fixture seeds, replay the same archive twice, and render JSON and Markdown. Assert the two runs agree on requests, source/institution attribution, evidence and stop reasons. Both arms use the same caps; an uncaptured URL consumes a replay slot, is reported as an archive miss and never triggers outbound I/O. A denied entry path does not prevent work on a permitted declared sitemap in the sitemap arm.
9. In the paid model milestone, kill a subprocess after scripted model dispatch but before its result is persisted. Resume the same campaign and verify one total dispatch, one retained reservation and no recovered classification. Reconcile the bill and verify the classification remains unresolved and is not replayed.
10. Discover 13 families and finish all persisted selected samples: report completed with sampling skips. Exhaust the request budget with selected pages outstanding: report partial and retain the outstanding selection.
11. Freeze an offline, manually labeled classification set with independent templates and positive, negative and ambiguous ground truth for each evaluated field. Label display/location assertions at the subject level. Report cases evaluated and per-field correct positives, false positives, misses and abstentions by method; abstentions on labeled positives also count as missed positives. The fixture gate rejects false subject-bound display/location claims and requires at least one correctly evidenced labeled positive for each display/location field claimed as supported. An always-unknown classifier must show missed positives and fail the gate, not report perfect accuracy. Keep scripted model results separate from deterministic results and never present either as live-model accuracy.
12. On a linked fixture archive, put useful pages behind different branches so that known pages are missed at discovery, selection, fetching and interpretation respectively. Assert their first missed stages and the matched-budget decision. Include two named institutions sharing a source with evidence for only one; request and source counts deduplicate correctly without crediting the second institution. Verify that an archive gap capable of changing the decision yields inconclusive, not a policy winner.

## Assumptions and contingencies
- The selected deliverable is a probe engine. SQLite and a CLI deliberately replace Hatchet/PostgreSQL at this stage; production indexing, artwork identity merging and scheduling are not implemented by this plan.
- Paid provider keys, model IDs and prices are supplied at runtime, never invented. Without them the same engine runs deterministic direct-only probes and records unresolved classifications/tiers; it does not pretend paid integrations succeeded.
- Museum software conventions begin with verified Omeka S, IIIF and generic structured/HTML rules. Unknown/proprietary deployments remain candidates for model-assisted sampling, not unsupported claims of platform compatibility.
- Budget enforcement bounds admitted operations against configured provider ceilings, not total cloud compute, provider-internal browser subrequests or unknown billing policies. Disable a paid fetch tier if its price ceiling or destination enforcement cannot be established; report which requirement is missing.
- Live probing may discover no useful evidence or only blocked sites. Successful implementation preserves that result with evidence and stop reasons rather than fabricating extraction or completeness.
